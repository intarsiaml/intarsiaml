## Brief

Lane `memlong`, cutover blocker 6. Prepare and smoke-test a long (about 11 h, overnight) mixed-traffic memory run of current main with NO malloc_trim calls. The coordinator then launches the long run itself. The lane does not wait for it.

Repo intarsiaml. Worktree `/opt/code/intarsiaml/.worktrees/memlong` (branch `memlong`, from origin/main eeca95f8e). All scratch and build dirs inside it.

### Context
- memmix (150 min, spark1, trim every 15 min) found the live heap flat. Arena committed size still rose about +190 MB/h, so an un-trimmed plateau was not shown.
- The suspected source was the prefix store's host buffers (`vec![0u8; n]` of many sizes).
- Since then PR #470 made `INTARSIA_PREFIX_STORE_PREFAULT` default-on for CUDA. New store host buffers are now their own page-aligned mmaps (huge pages from 2 MiB), not malloc. That may by itself remove the retention. This run tests current main as it ships.
- Also new on main: KV-once (#473) and CUDA copy drafts (#474, mb1 only, so not reached here).

### Do
1. `scripts/memlong/run.sh`: one self-contained script under ONE fleetq job, no babysitting. Builds nothing (prebuilt binary path). Starts our server on spark1 as memmix's main run did (35B NVFP4, `serve --max-batch 2 --prefix-store on`, shipping defaults, only stats env). Drives memmix's mixed traffic (`scripts/memmix/mixed.py`, same mix, fresh seeds, looping) for DURATION seconds. Samples every 60 s: RssAnon, glibc arena stats (libmemstat, NO trim calls), store host-tier bytes, MemAvailable, threads, fds. Writes CSVs and logs to a box dir, copies them to `docs/results/2026-11-20-memlong/raw/`, kills the server, removes the box dir, same cleanup on SIGTERM. Stops early if MemAvailable < 15 GB or the server dies and records why. Prints one final summary line.
2. `scripts/memlong/analyze.py`: memmix-style fits (slope +- SE of RssAnon, live heap, arena committed size from minute 30 and from hour 3) and a plateau test (last third vs first).
3. Build the release CUDA binary of main on spark1 through fleetq (`--load cpu`, `MAX_JOBS=4`). 20-minute smoke of run.sh through fleetq; confirm CSVs fill, analyze.py runs, SIGTERM cleanup works (second short run, killed).
4. Commit scripts and doc skeleton, push the branch, no PR.
5. Report the exact long-job command (DURATION 39600 s) and spark1's memory need beside vLLM; do not start the long run.

### Fleet rules
Every spark build / server / benchmark goes through fleetq. No `--force` / `--no-queue`, never release another owner's job, do not stop spark1's vLLM. GB10: 121 GB unified; budget = server + vLLM (~34 GB) + 10 GB OS; kill the server below 15 GB available. No tool call or wait over 4 min. At the end: no fleetq slot held, no server running.

### Residual growth

`RssAnon` +3.1 MB/h from minute 30 decomposes into arena committed +5.2, mmapped chunks 0, outside malloc -2.1 (the approximation described above); inside the arenas the live heap is +2.0 +- 2.2 (not different from zero) and free chunks +3 MB/h. So whatever remains is allocator-side, in the small (1.4 GB) malloc heap, and is smaller than the noise of any single hour's mean (hourly `RssAnon` means 10,116 to 10,222 MB with no ordering). The store itself, the only large consumer (8.0 GB outside malloc, 8.2 to 8.6 GB host tier at its budget), does not grow.
