# DSv4.1 TP=2 decode: direct RDMA exchange against NCCL (lane dsv41/rdma, 2026-11-02)

Branch `dsv41/rdma` from origin/main `4d9a5190e`. Spark dir `~/intarsia-dsv41-rdma`. Raw: `2026-11-02-dsv41-rdma/` (`step1-nccl-cost.txt`, `raw/`). Microbench: `tools/dsv41/rdma_bench/rdma_bench.cu`; trace analysis: `scripts/dsv41-tp2/nccl_cost.py`.

## Result

**Go.** With `INTARSIA_DSV41_RDMA` the 80 f32 all-reduces of a DSv4.1 decode / verify pass go over RDMA instead of NCCL: **2.0 to 2.8 ms less a pass (1 to 5 rows), +3.2 tok/s (+6.2 %) over all kinds, code 69.4 to 73.8 tok/s (target 71.2), prose 42.4 to 45.1 (target 44.8)**, both targets met, in two same-window ABAB pairs that agree to 0.3 ms a pass and 0.4 tok/s. Greedy output is token-identical (golden 640/640), because the exchange is bitwise the NCCL pair. Default on for a DeepSeek-V4.1 model when the build has libibverbs and `NCCL_IB_HCA` names the devices; `INTARSIA_DSV41_RDMA=0` is NCCL.

The microbench gate passed first (step 3, below): median 11.3 / 12.7 / 14.9 us at 20 / 40 / 80 KB against 27 / 31 / 38 us for NCCL, two rails. One rail misses at 80 KB (17.2 us).

Gates on head `99d13f76f` (see "Gates" below for ids and the one caveat: origin/main moved to `c269ded36` meanwhile).

## 1. What the collectives cost today (step 1)

Trace (read from the lane's `.scratch/w1/` before the coordinator removed that worktree; the committed `docs/results/2026-11-02-dsv41-group/w1/` holds only rank 0's last 3 passes, so `nccl_cost.py` cannot be re-run from the committed files, and `step1-nccl-cost.txt` is the saved output of the run on the full two-rank trace): `dsv41-group` window W1 (fleetq #7953, binary `1f9b6584f` = main's code, shipped defaults, `nsys --cuda-graph-trace=node`, 30 big passes of both ranks; `step1-nccl-cost.txt`). A pass has **83 collectives: 80 f32 all-reduces** (the `AllReduceInto` after the attention output projection and after the MoE, two a layer; the partial is `[rows, 5120]` f32, so **20 KB a row: 20 / 40 / 60 / 80 / 100 KB for 1 to 5 rows**), 2 bf16 all-reduces (Engram embeddings) and 1 all-gather (logits).

| per pass, median | ms |
|---|---:|
| rank 0 GPU span (traced; the real 1-row pass is 31 ms, nsys inflates) | 41.3 |
| NCCL kernel time, rank 0 / rank 1 | 4.2 / 4.5 |

Per call (min over the ranks): f32 all-reduce median 35.1 us (p10 24.9, p90 59.2), bf16 30.5, all-gather 82.9.

- **Most an exchange could win: 3.4 ms a pass** (all of the 3.38 ms, a free exchange). **Skew is the 2.0 ms**: a faster transport cannot remove it, the early rank waits for the late one whatever carries the bytes.
- Realistic: the 80 f32 calls at (NCCL - RDMA) of 16 to 25 us (below) = **1.3 to 2.0 ms a pass**.
- Per token: the shipped k = 4 gives 2.38 tokens a round (decode2), prose 2.18 (graphs doc). The code gap (69.2 against 71.2) is 0.41 ms a token = about 1.0 ms a pass; the prose gap (42.4 against 44.8) is 1.26 ms a token = **about 2.7 ms a pass**. So the realistic saving closes code and leaves about half of the prose gap.
- Caveat: `--cuda-graph-trace=node` adds a cost per node, so the traced durations are somewhat long; the bench's NCCL (27 us at 20 KB, 41 us at 100 KB) agrees with the trace's 35 us median for the 1-to-5-row mix, so the two projections coincide.

## 2. How TensorFold's exchange works, and whether we can use it (step 2)

Source: `zig/src/families/dsv41/rdma.zig`, `zig/kernels/cuda/dsv41/rdma_gather.cu`, `rdma_bench_main.zig`.

- **Registered**: pinned host memory (`mmap` + `mlock` + `cuMemHostRegister(portable | devicemap)`, device pointer by `cuMemHostGetDevicePointer`; on GB10 this takes the coherent path where `cuMemHostAlloc` takes an uncached one): a send ring (slots x max bytes), a receive ring (slots x world x max bytes) and a metadata block (flags per slot and peer, doorbell, sizes, sent, abort word). Both rings are `ibv_reg_mr`-registered (local + remote write). One RC queue pair per peer and rail, 256 zero-length receives posted.
- **Signal**: the stage kernel copies this rank's slice into its send slot, `__threadfence_system`, and the last block stores the doorbell (`st.relaxed.sys`). A **host proxy thread** spins on the doorbell, posts one `RDMA_WRITE_WITH_IMM` per rail (the immediate is the sequence number) into the peer's receive slot, polls the completion queue, and on a receive completion publishes `flags[slot][peer] = seq` in pinned memory. The collect kernel spins on that flag with `ld.acquire.sys`, then reads the slot. The sequence number is device state (`*seq`), not a kernel argument.
- **Under a recorded graph**: both are ordinary kernels (the proxy is outside the graph), so they capture and replay like any other; TF's bench replays 50-gather graphs. No host node, no `cudaLaunchHostFunc`, no stream callback. An optional programmatic-dependent-launch variant (`griddepcontrol`) is TF's default, not needed here.
- **Requirements**: libibverbs (rdma-core, installed), an active RoCE port (CX7 `rocep1s0f1` and `roceP2p1s0f1`, 200 Gb/s each, MTU 4096), a GID index (**3**, RoCE v2 over IPv4, the one NCCL uses here; TF's default 5 does not exist on these HCAs), `RLIMIT_MEMLOCK` unlimited (it is, on both Sparks; a container needs `--ulimit memlock=-1 --cap-add IPC_LOCK --device /dev/infiniband`, as TF's `start.sh` passes), `cuMemHostRegister` (allowed), and one spinning host core a rank (TF naps it when idle). **No kernel module, no driver or system setting, no `nvidia-peermem`, no GPUDirect, no permission change**: nothing to stop and report.
- Ordering: with world 2 the sum `own + peer` equals `peer + own` bit for bit, so the result is bitwise the NCCL all-reduce (checked below).

## 3. Microbench (step 3)

Program `rdma_bench.cu` (one process a rank, TCP side channel for the queue-pair info, NCCL joined in the same process with run-full.sh's exact settings: 2 channels, 1 MiB buffer, both HCAs, GID 3). Per call: `[spin kernel: 100 us of device time, stamps t_start] [exchange] [stamp t_done]`, 64 calls in a captured graph, replayed 30 to 40 times, device `%globaltimer` stamps. Paths: `nccl` = `ncclAllReduce` f32 (out of place) + the f32 -> bf16 round kernel = `Comm::all_reduce_sum_into` as the engine runs it; `rdma` = stage kernel + collect kernel (sum + round); `null` = two empty kernels (the harness floor: 1.4 us); `pp` = ping-pong, rank 0 stages then collects, rank 1 collects then stages, RTT / 2.

How to read the numbers. A symmetric exchange between two ranks that start `d` us apart costs the early rank `d` + the exchange and the late rank the exchange minus `d`; the ranks then alternate roles, so each rank's latency is bimodal (5 and 17 us) and its median is not the exchange. The **mean of the two ranks' latencies for the same call** is independent of the offset, and it equals the ping-pong RTT / 2 (11.7 against 11.8, 13.6 against 13.7, 17.0 against 17.1 us on one rail): that is the one-shot, skew-free latency, and it is what the table gives (median and p99 over 1860 to 2480 calls). NCCL needs no such step (its two ranks end together: min, mean and max agree within 1 us). Bitwise check: 25600 bf16 values of the NCCL path against the RDMA path, 0 differ, on both ranks, rail 1 and rail 2.

fleetq: #8018 (first runs, one rail, tuning knobs), #8038 (decomposition, two rails, ping-pong, memory load), owner `claude-rdma`, `--host spark1,spark2 --quiet gpu,cpu`, vLLM up on both (the prefill lane's own windows ran around mine). Proxy thread pinned to an X925 core (7) unless noted; pinning, PDL, stage blocks (4 / 16 / 32) and collect blocks (4 / 16 / 48) moved nothing outside 0.5 us (`raw/bench1-r0-v-*.log`).

One-shot latency in us, median (p99), gap 100 us, quiet memory (`raw/bench2-r0-rail2.log`, `bench2-r0-hog0.log`):

Where the time goes (rank-local, 2 rails): stage start to doorbell 3.1 us (launch gap 1.4 + the copy into pinned memory, flat in size), doorbell to the peer's flag 7 to 11 us (proxy, NIC, wire, peer proxy; the part that grows with size: 80 KB over one rail is 12.8 us of it, over two 10.5), flag to result 1.0 to 1.3 us.

**Gate: under 15 us at 20 to 80 KB and at least 1 ms a pass: passed with two rails (median 11.3 / 12.7 / 14.9 us, 1.3 to 1.95 ms a pass); one rail fails at 80 KB (17.2 us).** The p99 at 80 KB (16.0 us) is just over the line.

Under DRAM load (a read-hog kernel on 6 SMs beside the exchange; the pass streams about 250 GB/s through the same LPDDR; `raw/bench2-r0-hog6.log`) both paths slow: 20 KB RDMA 34 / NCCL 59 us, 80 KB 42 / 93 us; with 24 SMs of hog (`hog24`) 200 / 260 and 195 / 350 us. The hog is harsher than the pass (the trace's NCCL median, 35 us, is near the quiet bench's, not the loaded one's), but it shows RDMA's lead holds and the in-pass number will sit between the quiet and the loaded rows.

## 4. The engine path (step 4)

Files: `kernels/cuda/ik_rdma.cu` (the bench's kernels and proxy as a C ABI; compiled with `-DIK_HAVE_VERBS` and `-libverbs` only when `infiniband/verbs.h` and `libibverbs.so` exist, otherwise stubs; `build.rs`), `crates/intarsia-backend-cuda/src/rdma.rs` (`RdmaComm`: wraps the NCCL `Comm`, takes over `all_reduce_sum_into` of an f32 partial into bf16 on stream 0 up to 256 KiB, everything else, and every prefill chunk above 256 KiB, stays NCCL), `nccl::create_with_rdma` (the two ranks swap one byte on the control TCP stream: a difference in the setting is an error, not a hang; then the queue-pair info), `crates/intarsia-cli/src/common.rs` (`rdma_wanted`: unset = on for a DSv4.1 config when `rdma::usable()`; `0` off; `1` on for any model). Devices and GID come from `NCCL_IB_HCA` and `NCCL_IB_GID_INDEX` (run-full.sh already sets both). A dead peer or a failed work completion sets an abort word; the waiting kernels `__trap()` after 20 s or at once, so a stuck exchange fails the pass instead of summing stale bytes. The proxy thread spins; after 20 ms with no traffic it naps 20 us a turn (an idle server pays at most that on the first exchange). Row in `docs/tuning.md`; unit tests for the handshake and the device parsing in `rdma.rs`.

A/B, same window, same binary (`99d13f76f` minus the default flip, which only changes what unset means), `INTARSIA_DSV41_RDMA=0 / 1 / 0 / 1` through `run-full.sh` `AB=`, `STEPS=lcat`, `CAT_TOKENS=256`, localeval `categories-rcp` + `chat-rcp` (32 requests a arm), spec trace on in all four. fleetq #8098 (`wA2/`), tok/s by kind (`raw/catspeed-A2.txt`):
