# M35 Metal: split-KV decode attention head split (G = 8, D = 256)

Branch `lane-m35/sp-attn`, base d99cfa73 (PR #70 head). Qwen3.6-35B-A3B NVFP4, M5 Max, Metal.

Cause: `attn_decode_bf16_splitkv_g8` keeps q and the accumulator of all 8 query heads of a kv head in registers
(2 x 8 x 8 = 128 floats per lane at D = 256, one key per simdgroup step) and, with `TG_FLOATS = 4096`, only 2 simdgroups
per threadgroup. 2 threadgroups at 50 keys, 30 at 1.8k: 270 us and 800 us per call in the per-kernel profile.

Fix: the 8 heads of a kv head run as 4 threadgroups of 2 heads (`OpP::s1` = head split HS, `attn::head_split`), each
reading the kv head's keys / values (the readers share the caches). The split policy, the simdgroup rule and the grid see
the 4 x Nkv virtual kv heads; the G0b multi-row kernels take the same split, so rows stay bitwise the 1-row launch.
HS = 1 (every other shape, the 8B included) runs the same code path and arithmetic as before. Each head's arithmetic is
independent, so HS changes bits only through the simdgroup count (2 -> 4 at the device position). `INTARSIA_METAL_ATTN_HS=<n>`
overrides HS (diagnostic: 1 is the old launch).
