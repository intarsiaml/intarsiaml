# DSv4.1 TP=2 CUDA prefill on current main: baseline, like-for-like class table, and the one lever left (encoder-only dead chunks)

Lane `dsv41/prefill3`, branch `dsv41/prefill3`, 2026-11-05. Base: `origin/main` 9783878af (binary `1ffa366b4`, the `replay` merge; no code differs between the two). No go-ahead or course correction message was received during the lane.

**Result.** Main still ran layers 20-39 on the last 128 rows of **every** prefill chunk. TensorFold (TF) does that for the last chunk only, because the earlier chunks' decoder-half work is never read again. The branch skips it too (`INTARSIA_DSV41_REPLAY_SKIP`, default on). Output is bit-identical. 4106-token prompt: 2517 -> 2353 ms in the trace (-6.5 %); localeval 4K +3.0 % / +8.3 % in two ABAB pairs, 16K +8 / +11 %, 32K +9.5 / +13 %. Nothing else remaining is above 3 % of 4K prefill by itself (section 3).

## 3. The lever and what remains

**Rule.** The engine prefills a prompt in chunks; each chunk's replay floor is `rows so far - 128`, so every chunk of at least 128 rows ran the decoder half on its last 128 rows. A later chunk reads decoder-layer window keys only from `end_k - 128` on (the DSpark stage rings the same), so the earlier chunk's decoder-half writes are never read when a live later call covers its positions. `replay::decoder_dead(end, ahead, chunk, window)` decides it (unit test against a brute-force simulation over windows 1, 4, 128 and many chunk/total shapes). For a 4106-token prompt only chunk 1 is dead (the 10-row tail's floor 3978 is below chunk 2's end 4096); for 32K it is 15 of 16 chunks. Rank 0 decides per chunk and sends `FWD_ENCODER` (new forward flag) to rank 1; the handshake fingerprint now says `replay skip`, so a peer without it refuses to pair. `INTARSIA_DSV41_REPLAY_SKIP=0` restores the old schedule; read by rank 0 only. The compressed KV and index keys of the decoder half belong to layer 20's kv-source update, which the encoder part of every chunk still writes.

**Measured gap (floor = TF's schedule).** The 4106 prompt: 164 ms of 2517 ms, 6.5 %, above the 3 % bar. By the time of the data this was a trace-count finding, not a kernel estimate, so no kernel-bench discount applies.

**Remaining, ranked** (candidate - TF at 4106 tokens; 3 % of the 2353 ms wall is 70 ms): attention +64 ms (2.7 %; the 1.65x kernel gap, TF-shaped block already ruled out at +0.1 %), gate/up +64 (2.7 %; past 512 rows, bench figures discounted 2-3x by E5/E3), router gate +56 (2.4 %; `dense_f16w_vec`, 2.1 ms per 2048 rows against TF's cutlass sgemm 0.74 ms: bitwise would need the same f32 accumulation order, not checked), NCCL +23 (1 %), HC +10 (0.4 %). **No single one clears 3 %, and the two largest are the ones already attacked.** Not built.
