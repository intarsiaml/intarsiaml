### Ranked fixes (estimated gains)

1. **Metal: a bandwidth-bound row-exact multi-row MXFP4 GEMV** (each row bitwise the M = 1 kernel, as today's `_m8` claims; share the widened activations
   across several output rows per simdgroup and stage them once). Target M=3 <= 1.25x and M=8 <= 1.8x of M=1 (today 2.2x / 4.8x). Estimate: verify
   at 3 rows 60 -> ~44 ms, MTP k2 pass 68 -> ~52 ms, **MTP k2 on Metal +25-35 % (natural 4k ~31 -> ~40 tok/s)**, and k3/k4 become worth trying.
   Lossless by construction; it is also the prerequisite of any DFlash2 on Metal. No user decision. **Phase 2 starts here.**
2. **HIP: tensor-parallel DFlash2 draft** (draft layers split over both ranks as the MTP head already is, vocab-parallel draft head with a per-rank top-16
   and merge): draft 13.8 -> ~7 ms, pass ~38 -> ~31 ms, **DFlash2 +20-25 %** in every category.
3. **HIP: device-side top-k and selector** (no 7 MB logits download, no host walk): -1.4 ms a pass, +4 %.
4. **HIP: recorded tp2 speculative pass and run-ahead submission** (Radiance records draft + verify and submits 99 % of steps ahead): size set by w1's
   off vs `--no-graphs` and the op tables; plausibly -3 to -5 ms a pass.
5. **Metal: DFlash2 on Metal** (`DynConv` kernel, windowed attention, the block pass and selector; the draft is local): with fix 1, a k7 chain pass
   ~55 + ~12 ms; ~2.5 tokens on prose, 5.3 on code: about MTP's rate on prose, ~1.6x on code. Several days.
6. **Both: tree drafts** (TensorFold's ~15-node trees, ~1.9x the tokens of our chain on Metal): the acceptance half of the Metal gap; largest work.

Expected after 1-4: HIP DFlash2 ~38 -> ~26-28 ms a pass (Radiance 17.7): 0.44x -> ~0.65x. Metal: 0.34x -> ~0.45x with fix 1, more only with 5 and 6.

## Phase 2, fix 1 (Metal): M-row MXFP4 GEMV, `INTARSIA_METAL_MXFP4_MR` (default off)

### What changed

`kernels/metal/mxfp4.metal` `mxfp4_gemv_mr_impl<M, P>` (M = 2..8 exact, P = 2 or 4 output rows per simdgroup; 28 shaders
`mxfp4_gemv_{bf16,f32}_mr{M}p{P}`), picked by `crates/intarsia-backend-metal/src/mxfp4.rs` for `matmul_mxfp4_gemv` calls of 2..8 rows when
`INTARSIA_METAL_MXFP4_MR` is `1` (auto: P = 4 for M <= 3 with N <= 8192, P = 2 for other M 2..4 and M = 8, the old `_m8` for M 5..7, which measured
slower), `2` or `4` (forced P). Each weight word is decoded once per simdgroup row and each activation word widened once per simdgroup; every
(weight row, activation row) pair keeps the one-row shader's fma chain and lane order, so every row is bitwise the M = 1 call. M = 1 and M > 8 are untouched.

### Gates so far

* Bitwise (tests/mxfp4_gemv.rs `m_row_shaders_are_bitwise_the_one_row_call_per_row`, endor GPU, fleetq #8770): 672 cases (N 37 / 130 / 515 / 64 with
  tails, K 32 / 544 / 5120 / 17408, M 2..8, knob 1 / 2 / 4, bf16 and f32 out, W4A16 fused and W4A4 pre-pass, x aligned and at +4 bytes): every row
  equals the M = 1 call and the whole output equals the `_m8` shader's. The pinned-hash and older tests of the file pass. **2 of 2 planted faults
  caught** (reverse summation order in one weight row; a row-stride slip), `raw/metal-mr2/`.
* Kernel bench (`raw/metal-mr2/steps.log`; x of the M = 1 call of the same run; `_m8` -> auto): M = 2: 1.15-1.85x -> 0.82-1.22x; **M = 3: 1.51-2.32x ->
  0.95-1.42x**; M = 4: 1.89-2.84x -> 1.19-2.02x; M = 8: 3.30-4.91x -> 2.74-4.08x.

### Pre-registered speed rule (written before the end-to-end run)

Same binary, Metal, the 27B with the default spec (MTP k2, pipelined step), a fresh `serve` per visit, visits A B A B (A = knob unset, B = `1`), localeval
suite cells `speed-spec` (natural-v1) and `speed-plain` (filler), 256 tokens, 3 reps. **Ship as an opt-in (default stays off; a flip is the user's
call) if B / A of the two-visit medians is >= 1.10 at natural-v1 1k and 4k, and no cell is below 0.98.** Plus: `--spec off` speed-plain B / A within
0.97..1.03 (the M = 1 path is untouched); greedy ids with the knob on equal `--spec off` at MTP k1..k6, short and 4k prompts; `kernels test` and `plan
show` unchanged with the knob unset (the 8B, 27B, 35B on Metal).
