### 0.2 Quant formats the Metal backend supports today

bf16 everything (GEMV variants, tiled GEMM, NAX GEMM on metal4), and OCP MXFP4 GEMV (`matmul_mxfp4_gemv`, M1 drill).
No FP8, no NVFP4, no MLX affine.

### 0.4 How CUDA / HIP / CPU implement them

| Op | CPU reference | HIP (kernels/hip) | CUDA (kernels/cuda) |
|---|---|---|---|
| matmul_fp8 | `quant::reference::matmul_fp8` (W8A8 static when `input_scale > 0`, else W8A16) | `fp8.hip`: gemv (M 1..4, v2), mma / mma_v2 / mma_f8 for prefill | `fp8.cu`, `fp8_gemm*.cu` |
| matmul_nvfp4 | `matmul_nvfp4`: `fp4 * e4m3(block16) * global` | `nvfp4.hip`: gemv (M 1..8), mma | `nvfp4.cu`, `nvfp4_gemm.cu` |
| moe_topk | top-k of logits, softmax over selected (norm_topk) | `moe.hip` topk v1/v2 | `moe.cu` |
| moe_experts | per token sum_k w_k * down(silu(gate) * up), bf16 rounding points | `moe.hip` experts v1/v2/v3 (grouped) | `moe.cu`, `moe_decode.cu`, `moe_grouped.cu`, `moe_w4a16.cu` |
| moe_combine | `routed + sigmoid(g) * shared` | `moe_combine_bf16` | `moe.cu` |
| gate_split / sigmoid_mul | `gdn::gate_split`, `gdn::sigmoid_mul` | `elementwise.hip` | `elementwise.cu` |
| gdn_conv | depthwise causal conv K=4 + SiLU, f32 state `[C,K-1]` | `gdn.hip` conv + conv_state | `gdn.cu` |
| gdn_delta_rule | gated delta rule, f32 state `[Hv,dv,dk]` | `gdn.hip` sequential over tokens (v2 for dk=128) | `gdn.cu` sequential |

### 0.5 Choice: the NVFP4 checkpoint

It is the only complete 35B checkpoint on endor, it is what users run on CUDA / HIP, and the 35B accuracy goldens
(`golden/qwen36-35b-a3b-nvfp4-vllm{,-long}-top20.safetensors`) are vLLM runs of this exact checkpoint, so the gate
compares like with like. Kernel work: FP8 and NVFP4 matmuls (GEMV + a prefill path), the MoE trio, GDN conv + delta
rule, two elementwise helpers. Memory: 22 GB weights; a 32 GB fleetq lease is enough.

Work split (coordinator-approved parallelism): three sub-agent worktrees branched from this lane branch:
GDN + gated-attention helpers; FP8 / NVFP4 matmuls; MoE topk / experts / combine. Each accepted on
`intarsia kernels test --backend metal` for its ops with 0 FAIL, reviewed, then merged here.

## 1. Kernels (merged from three sub-agent branches)

| Op | Kernel(s) | Shape | Notes |
|---|---|---|---|
| gate_split, sigmoid_mul | `gate_split_bf16`, `sigmoid_mul_bf16` (gdn.metal) | elementwise | one f32 op, one bf16 rounding |
| gdn_conv | `gdn_conv_bf16` (per K 2..8) + `gdn_conv_state` | thread per channel | state pass for chunked calls and T < K-1 |
| gdn_delta_rule | `gdn_delta_rule_bf16` (dk 32/64/128/256) | simdgroup per (value head, state row), sequential over T in one dispatch | state row in registers, next token prefetched |
| moe_topk | `moe_topk_bf16` (bf16 / f32 logits) | simdgroup per token | ties to lowest index |
| moe_experts | `moe_experts_bf16` | decode T*K <= 16: per-pair gate+up GEMV, then down + weighted sum in k order; prefill: GPU group-by-expert, 32x32 simdgroup-matrix tiles per expert, per-token gather in k order | scratch `moe_experts_scratch`; deterministic (slot order from atomics changes no value) |
| moe_combine | `moe_combine_bf16` | elementwise | |
| matmul_fp8 | `matmul_fp8_gemv` (M <= 8, prio 10), `matmul_fp8_mma` (any M) | GEMV: q(x) staged in threadgroup memory; GEMM: x QDQ'd into scratch then 64x64 simdgroup-matrix bf16 GEMM | W8A8 quantiser bit-exact vs cpu over all bf16 inputs |
| matmul_nvfp4 | `matmul_nvfp4_gemv` (M <= 8), `matmul_nvfp4_mma` (any M) | B tile = fp4 * block scale (exact in bf16), global scale in the epilogue | also serves lm_head (NVFP4, f32 out) |

Weights are read with 8-byte loads at most: real shard tensors sit at 8 mod 16 (§0). A weight that is not 8-byte aligned is
refused with `Error::invalid` at launch. Tests bind weights at 8 mod 16 (tests/quant.rs, tests/moe.rs). Every program-scope
shader symbol carries a per-file prefix (`gdn_`, `moe_`, `fp8_`, `nv_`), because all `.air` files link into one metallib.
No core change. The changes stay inside `crates/intarsia-backend-metal` and `kernels/metal`.
