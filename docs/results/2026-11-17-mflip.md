client prompts as lane mherd ([2026-11-17-mherd.md](2026-11-17-mherd.md)); every run through fleetq (`--quiet gpu,cpu`, `--mem 50`, jobs #9929-#9935). Scripts `scripts/mflip/` (`flip.sh`, `burst.py`, `analyze.py`, `lib.sh`; it reuses

## 2. Method

Same as mherd: one server per visit (env read at startup), fresh store, `INTARSIA_CB_NO_REUSE=1`, `--profile-every 0 --no-supervisor --no-ui`, thermal level waited to 0 (up to 90 s; a few visits started at level 1), token-id prompts on
`/v1/completions`, greedy, `ignore_eos`, 48 tokens, TTFT from each request's own submit. A = features off, B = on. **ABBA, one pass (A1 B1 B2 A2) per cell, 2 seeds per visit = 4 cells per arm**, except cell 1 which ran
ABBA twice (8 visits, 8 cells per arm). (The brief said "at least 2 repeats": each arm has two visits and two seeds per visit; only cell 1 has the mherd-sized 8 visits.) Gate: every reply in every cell (burst and solo, both arms)
compared with the arm-A solo reply of the same prompt (store on, one request at a time, 16384 cached).

* herd shape: `--max-seq 17408 --prefix-store on`, N requests = a new 16448-token shared prefix + 200 own tokens each. sjf shape (as mherd): no store, 40000-token prompt at t=0, 1000-token at +2 s, `--max-batch 4` (`--max-batch 16` in cell 3).
* **Spec config.** Cells 1, 3, 4: `--spec off` (as mherd, isolates the two features). Cell 2: **no `--spec` flag and no env**, so the shipped default applies. The server log (`raw/herd-35b-default-mb8/*/startup-lines.txt`) shows:
  `--spec mtp --spec-k 2: the default of recipe qwen3_5_moe on metal at tp=1`; `batched MTP N=1 (recipe qwen3_5_moe, [tuning.metal] batched_mtp): a sequence drafts while at most 1 sequences decode`; `prefix store: --spec mtp drafts on store
  requests` (`INTARSIA_MTP_STORE` defaults on for Metal). So batched MTP is **on by default on Metal** through the recipe (`batched_mtp = 1`, N = 1; drafting only while one sequence decodes), and nothing had to be enabled by env var
  (unlike mstore's 27B, whose recipe has no `batched_mtp`). With 2 or more sequences decoding MTP does not draft, so herd/sjf cells exercise MTP mainly at the tails and in the solo reference cells.

**Is any follower slower with herd on? No.** Per arrival index, on minus off (per seed): at 0.5 s every follower is faster (index 1: -1.9 / -2.2 s, index 7: -3.6 / -4.6 s), the leader (index 0) is +0.1 / -0.1 s; at 2 s all
indices are within +/-0.3 s, the worst on-arm excess is +0.09 s (noise: run-to-run spread of these 0.2-0.4 s TTFTs is that size). At 2 s the leader's prefix is already in the store when the third request arrives (16 K takes 3.6 s),
so herd has nothing to hold and nothing to lose; followers 1 and 2 arrive during the leader's prefill and gain 0.1-0.3 s at most. Cached tokens off at 0.5 s: 8192 / 12288 / 16384 (the leader's capture grid reaches later followers only
as it prefills); on: 16384 for every follower. Ids: **256 / 256 equal** (12,288 ids).

## 8. Not verified

* ABBA once (n = 4 per arm) for cells 2-4, ABBA twice only for cell 1; cell-to-cell noise on this Mac was up to 15 % in mherd.
* Why the short prompt is served after the herd in cell 1 (4.7 s, not sjf's 1.6 s): no herd-only / sjf-only cell on the mix shape, scheduler counters not read.
* Cells 3 and 4 ran `--spec off`; herd x16 and staggered arrivals with MTP default were not run. MTP on vs off ids were not compared with each other.
* The 27B, prefix sizes other than 16448, and the sjf cell with a prefix store configured (mherd's sjf shape has none; cell 1 and the mix cells have both) at the 40K size.
* Thermal level 1 at the start of a few visits (A1/B1 of some cells); not excluded.
