# 2026-11-18 sysmsg: system message that is not first

CPU-only lane. No model run, no fleet box.

## Problem and reproduction

`POST /v1/chat/completions` with `user, assistant, system, user` returned HTTP 400. The source is the chat template, not
the server: the Qwen3.5, 3.6 and 3.8 templates (`crates/intarsia-server/tests/fixtures/qwen3_*_chat_template.jinja`) read
`messages[0]` as the system prompt, and in the message loop a system message with `not loop.first` runs
`raise_exception('System message must be at the beginning.')`. The error comes back through `blocking()` as a 400.
vLLM renders the same template and fails the same way, so the old behaviour was vLLM-compatible; nothing in docs/ or
`docs/decisions/LOG.md` promises anything else (no row mentions it). Test:
`midsystem::tests::templates_refuse_mid_system_and_error_names_the_fix` reproduces it on all three templates.

## Behaviour chosen

Default unchanged: still 400 (parity with vLLM, no silent prompt change), but the message now names the fix. New opt-in
`INTARSIA_SYSTEM_MIDCONV` (`docs/tuning.md` row), applied on `/v1/chat/completions` and `/v1/intarsia/prefill` (the
Anthropic route takes `system` as a top-level field, so it cannot produce the shape):

| value | rewrite | prefix stability |
|---|---|---|
| unset / `off` | none (400) | n/a |
| `user` | the message stays in place, role `user`, text prefixed `[System message]` | stable: turns before it render byte-for-byte as before, so a prefix store keeps hitting on the next request of the same conversation |
| `merge` | text appended to the leading system message (one is created if absent), message removed | unstable: the head of the prompt changes each time a reminder arrives, so the stored prefix of the earlier request no longer matches |

Why `user` is the one to prefer: it is append-only. `merge` keeps the model's "system" semantics but costs the prefix
store, and an agent that injects a reminder every turn would re-prefill the whole conversation each turn. Neither mode is
default; the flip is the user's call. Not covered: the `developer` role, a system message whose content is empty
(`user` mode renders just the prefix; `merge` drops it), and the model's quality on the rewritten prompt (not measured).

## Tests

- `midsystem::tests::*` (server lib, real templates of three models): refusal and error text; `user` output contains the
  user-role note and starts with the bytes of the shorter conversation; `merge` gives one system block; valid requests
  (no system, leading system, multi-turn) are unchanged by `rewrite` and render byte-identically in all three modes.
- `system_midconv_rewrites_only_when_asked` (tests/api.rs): HTTP level, roles seen by the template in off / user / merge.
- `cargo test -p intarsia-server`: 58 lib + 59 api tests pass. `cargo test -p intarsia-cli --test docs_env_vars`: pass.

## Revert

Remove the variable (unset is the default); or revert the PR: `crates/intarsia-server/src/midsystem.rs` and the three call
sites.
