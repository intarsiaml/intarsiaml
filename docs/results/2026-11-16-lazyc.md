# Lane lazyc: lazy admission cases on by default for CUDA (2026-11-16)

Verdict: **bitwise-neutral on CUDA, and it saves 10 s (35B) and 5 s (27B) of every warm `serve` start on a GB10.**
`plan::admit` now builds a kernel test case's random data only on an admission-cache miss (`PlanOptions::lazy_cases`, PR #393)
for CUDA as well as Metal. `INTARSIA_ADMIT_LAZY=0` turns it off; HIP and cpu stay off (HIP: tatooine is busy, not measured).

Machine: spark1 (GB10), vLLM `spark1-vllm` up beside it, binary built from this branch (`lazyc-` stamp), `serve --backend cuda
--max-seq 40000 --mem-budget 40 --profile-every 0 --no-supervisor --no-ui`, 35B = `nvidia/Qwen3.6-35B-A3B-NVFP4` with
`--max-batch 2` (recipe defaults: MTP k2, batched MTP/verify), 27B = `Qwen3.8-27B-Quark-AWQ-MXFP4` default. Scripts:
`scripts/lazyc/`, raw logs and plans: `docs/results/raw/2026-11-16-lazyc/`.

## Gate 1: warm `serve` start (time until `/health` answers)

Warm-up start first (a fresh binary has a cold cache key), a second warm start, then arms in order 0, 1, 1, 0.
Every timed start: 0 cases run, all cached.

| model | `INTARSIA_ADMIT_LAZY=0` | `INTARSIA_ADMIT_LAZY=1` | gain |
|---|---|---|---|
| 35B NVFP4 | 44.9, 45.7 s (mean 45.3) | 34.1, 36.6 s (mean 35.4) | 9.9 s (22 %) |
| 27B MXFP4 | 38.2, 41.6 s (mean 39.9) | 35.8, 34.6 s (mean 35.2) | 4.7 s (12 %) |

Gain is over the 1 s bar on both models. Most of a CUDA start is weight load (about 34 s here), so the relative gain is
smaller than Metal's (65 s to 2 s on the 27B).
