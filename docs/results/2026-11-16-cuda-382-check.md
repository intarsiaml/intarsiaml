## Result

**#382 works on CUDA when no MTP head is loaded, and does not reach the CUDA default config (MTP on at tp=1).** In the default config
every `restore` and `aligned` case of acc-4k still reuses nothing (`cached 0`) and the prefix-reuse gate fails. The cause is the MTP
exclusion #382 documents (`SequenceState::inner_snapshot_bufs`, `crates/intarsia-core/src/state.rs:541`, `self.mtp.is_some()` returns no
buffers, so a macro pass snapshots only at its end). That is the HIP doc's open item, now shown on CUDA's default serving path. Not
fixed here: an MTP snapshot needs the head's pending rows at the inner chunk end, which the pass has only at its end (design work).

Reading:
- Spec off: pre-#382 reuses nothing (as on HIP), #382 reuses at the plain schedule's lengths (2048 / 1024 / 4096), and every `aligned` row is "logits bit-identical to the cold run". Same cached lengths as the macro-off control.
- MTP on: the plain schedule (macro off) reuses, macro on does not. With macro on and an MTP head, `inner_snapshot_bufs` returns no buffers (`state.rs:541`; the `snap_from` logic at `model.rs:3306` has no MTP test of its own).
- Gate at the recipe chunk 2048 fails in every arm, including the pre-#382 tree and macro off, because of `long_code_4k continue`: warm and cold streams diverge at token 3 (3/32, "warm took 23776 cold took 1528"; its committed oracle is skipped because the golden's prompt ids differ). It is identical on the pre-#382 tree (also at chunk 1024), so not #382. At chunk 4096 only `chat_reuse_4k` is judged and the gate passes (spec off, macro on or off). A CUDA default-config (MTP) run at chunk 4096 was not made.
- The prefill / decode KL of the golden was not run (mode `reuse` only); the "golden gate" line in the logs is the reuse gate's.
- Open for decision (not done): CUDA serving defaults to MTP, so a request sharing part of an earlier prompt's macro step still re-prefills from the last end-of-pass snapshot; the fix is design work on the MTP snapshot (head pending rows).
