## Exact commands

All fleet commands went through fleetq; shell snippets abbreviated to what matters.

```

fleetq run --host tatooine --mem 0 --label "intarsiaml r9700 prep: copy Qwen3-8B weights from spark1" -- bash copy.sh
  # copy.sh:
  #   ssh spark1 'cd <snapshot b968826d...> && tar -chf - .' | ssh tatooine 'tar -xf - -C /data/models/intarsia/Qwen3-8B'
  #   ssh spark1 'cd ~/intarsiaml-golden && tar -cf - goldenlib.py golden.py prompts run.sh run_long.sh qwen3-8b.safetensors qwen3-8b-long.safetensors' \
  #     | ssh tatooine 'tar -xf - -C /data/models/intarsia/golden'
  # (tar -h dereferences the HF snapshot symlinks; used instead of rsync -L because rsync cannot hop spark1 -> tatooine without a direct route; ~25 min, ~11 MB/s)
fleetq run --host tatooine --mem 0 --label "...sha256 verify weights" -- bash sums.sh      # sha256sum on both ends, diff of sorted lists: IDENTICAL (18 files)

# 2. repo sync + image + check
fleetq run --host tatooine --mem 0 --label "...sync repo + build dev image" -- bash -c \
  'rsync -a --delete --exclude target --exclude .git --exclude golden --exclude tools/.venv /opt/code/intarsiaml/ tatooine:~/intarsiaml/ \
   && ssh tatooine "cd ~/intarsiaml/deploy/tatooine && docker build -q -t intarsia-hip-dev:rocm7.2.4-rust1.90.0 -f Dockerfile.hip-dev ."'
fleetq run --host tatooine --mem 0 --label "...cargo check in image" -- ssh tatooine 'cd ~/intarsiaml && deploy/tatooine/dev.sh cargo check --workspace'
fleetq run --host tatooine --mem 0 --label "...hipcc build smoke (no GPU run)" -- ssh tatooine \
  'cd ~/intarsiaml && deploy/tatooine/dev.sh bash -c "cd deploy/tatooine/smoke && hipcc --offload-arch=gfx1201 -O3 -o /target/smoke smoke.hip"'

# 3. GPU smoke (one lease)
fleetq acquire --host tatooine --takes-down radiance --mem 30 --label "intarsiaml r9700 prep: gpu smoke" --wait    # -> #1363
FLEETQ_JOB=1363 ssh tatooine systemctl --user stop radiance          # 00:10:16 EDT
FLEETQ_JOB=1363 ssh tatooine 'cd ~/intarsiaml && HIP_VISIBLE_DEVICES=0 FLEETQ_JOB=1363 deploy/tatooine/dev.sh /target/smoke'   # and =1, and unset

# 4. radiance source
fleetq run --host tatooine --mem 0 --label "...clone radiance source" -- ssh tatooine 'mkdir -p /data/src && cd /data/src && git clone https://codeberg.org/StillDeadcode/radiance'
  # then: git checkout v1.4.0 (detached); docker image inspect label org.opencontainers.image.revision=dc339b4cd239 matches
```

## Issues found and fixed during the prep (all in new files)

1. **Container saw no GPU**: `--group-add render` resolves inside the image to GID 109, while on the host `/dev/kfd` and
   `/dev/dri/renderD*` are group `render` = **993**. `dev.sh` now passes the numeric GIDs read from the device nodes
   (`stat -c %g /dev/kfd`, `renderD128`) plus `video`. (The container runs as the host uid:gid, `--user $(id -u):$(id -g)`,
   with `HOME=/tmp`, so files written into the mounted repo stay owned by the host user.)
2. Named volumes are created root-owned, so cargo could not write its registry: `dev.sh` creates them once with `chmod 0777`.
3. The first attempt to run a Docker command from a tool call that merely contained the text "docker run" was blocked by the
   fleetq guard; commands were split so each fleet command carries its own `fleetq run`/`FLEETQ_JOB`. (`FLEETQ_JOB=<id>` has
   to be a per-command prefix, `export` is rejected by the guard.)

## Open / blocking

- None blocking. Open decisions and unverified claims are listed in section 7 of `docs/research/radiance-port-plan.md`
  (KV layout for the radiance pack, collectives in single-process mode, `rad-convert` MXFP4 passthrough, tuning tables).
- Spark1 -> tatooine has no direct ssh trust (host key not accepted); copying goes through the Mac at ~11 MB/s. Adding
  tatooine to `spark1`'s `known_hosts` (and a key) would make the next 16 GB copy about 10x faster; not done (outside scope).
- `intarsia-backend-cuda` was not part of the check; the HIP backend crate does not exist yet.
- Radiance's `libr4d` was read, not compiled or run here. The first port milestone should compile `r4d_gemm_bf16_nt_m64`
  and `r4d_gemm_bf16_nt_tiled` standalone in this image and compare against `intarsia-backend-cpu` on Qwen3-8B shapes.
