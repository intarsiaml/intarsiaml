## 1. What blocked the run

- `fleetq status` shows `spark1 (spark-4e77) OFFLINE`, `spark1-vllm ... host offline`, from 01:50 to 03:55.
- ICMP to 192.168.1.95 answers (3 ms). TCP 22 accepts, then `Connection timed out during banner exchange`.
  Port 8000 (vLLM) refuses connections. The `spark1` ssh alias routes through Tailscale, which reports the node
  offline, so it times out earlier. This looks like a hung or thrashing host (kernel up, userspace not
  serving), not a network fault. Polling every 30 s for over two hours never got a banner.
- Cause unknown. The harness agent had an 8B HF golden job (4.6k tokens, top-20) running when the host went away
  and cannot say whether it was responsible. spark1 uses unified memory, so memory pressure from that job next
  to the 64 GB `spark1-vllm` reservation is the first suspect, but nothing observed proves it.
- I have no power control on the box. A person needs to power-cycle it.
- spark2 was not substituted: it has no cargo toolchain, no goldens or 35B checkpoint paths set up for this, and
  its vLLM serves a different role (`retro`), so an A/B against the "guidance" checkpoint there would not be the
  required comparison.

## 6. Honest gaps carried forward

- Everything in section 3. The largest risks are build errors in the never-linked CUDA Rust path, a silent
  graph fallback to eager on the real plan, and an accuracy regression from the new MoE and GEMM kernels
  (rel_l2 up to 3.5e-4 against the old kernel in the standalone check, a different summation order).
- vLLM serves an fp8 KV cache and we use bf16, so every 35B KL against it includes reference KV noise. Separating
  the two needs a vLLM started with `--kv-cache-dtype auto`, which was not allowed here.
- Reuse gate (`accuracy --mode reuse`) has run only on an attention-only model, never on GatedDeltaNet.
- The model-level MoE-vs-HF test the review asked for is still not built.
- Fusions (GDN conv+gating+recurrence, rmsnorm+residual) and multi-stream branches inside the engine's graph are
  not written. The replica says they are worth up to about 0.6 ms per token.
- Decode ABI change: `ik_rope_bf16`, `ik_kv_append_bf16`, `ik_attn_decode_bf16` and `ik_attn_decode_bf16_splitkv`
  gained a `pos` argument before `stream`; the HIP worktree (phase2a/hip) must adopt it.
- Residue on spark1 from earlier agents: `~/intarsiaml-harness`, `~/intarsiaml-golden/run8b.sh`, `acc.sh`, and
  the new goldens. No target directory of mine exists there (I never reached spark1).
