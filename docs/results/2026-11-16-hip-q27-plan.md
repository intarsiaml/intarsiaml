# `qualify` plans the Qwen3.8-27B on HIP again (2026-11-16, lane q27-plan)

Finding of lane b27-rerecord (`docs/results/2026-11-16-hip-27b-rerecord.md`): `intarsia qualify --backend hip` on the 27B stopped in its `plan`
stage, `1 op(s) selected a kernel that did not pass admission: attn_decode:attn_decode_bf16_splitkv_rows`, and `gate`, `acc-short`, `envelope`,
`tp` were "blocked by plan". `accuracy` and serving of the 27B were not affected.

## Cause

The kernel is admitted. Only the plan description says it is not.

* `attn_decode_bf16_splitkv_rows` is a row-table kernel (`crates/intarsia-backend-hip/src/kernels.rs:517`, `.row_table()`). The admission sweep skips row-table
  kernels (`crates/intarsia-core/src/admission.rs:1169`, `crates/intarsia-core/src/plan.rs` `admit`: no exact-shape case has a table of device addresses), and
  `Registry::select` counts one by the admission of the kernel it twins, here `attn_decode_bf16_splitkv`
  (`Registry::effective_admission`, `crates/intarsia-core/src/registry.rs:337`, lane rb3, `cbfc07fb4`). Its base is admitted on the 27B's shape
  (`plan.json` of the failed attempt: `attn_decode_bf16_splitkv ... admitted: true`).
* The plan description did not use that rule: `resolve` set `PlanOp::admitted` from the kernel's **own** state,
  `model.registry.admission(&c.kernel) == Some(Admission::Admitted)` (`crates/intarsia-core/src/plan.rs:578` before this change), which for a row-table kernel is
  `Untested` forever. `qualify`'s plan stage fails any op with `admitted != true` on a non-CPU backend (`crates/intarsia-cli/src/cmd/qualify.rs:1117-1148`).
* The op reaches the plan only with speculative decoding on: the verify probes (`Phase::Verify`, rows 2..=`verify_rows`) record the verify pass's one row-table
  attention launch. The 27B's recipe default is `--spec mtp --spec-k 4`. The 35B with spec off, and the 8B, have no such row (docs/results/2026-10-28-vat-verify-attn-rows.md
  section 1, already noted `admitted: false in the dry plan`).
* Shape: the 27B's attention is 24 query heads, 4 kv heads, head_dim 256 (`config.json` on tatooine; 6 query heads per kv head, inside
  `splitkv_ok`'s limit of 8). The shape is accepted at every row count 1..=16; there is no missing sweep case and no predicate gap.

Broke with `85c8c3093` (lane vat, 2026-10-28, "one row-table attention launch per layer for the verify rows"), which put a row-table kernel into the plan of a
model with spec on by default. The last passing 27B HIP qualify plan stage was 2026-10-25 (`docs/results/2026-10-25-mx-fold-default.md`: doctor, recipe, plan,
kernels (66 kernels / 1465 cases), gate, bench PASS); nobody ran qualify plan on the 27B on HIP between 10-28 and 11-16. The same applies to any model whose plan
records a row-table twin (HIP `serve --max-batch N`: `gdn_conv_bf16_rows`, `kv_append_bf16_rows`, ...), on every backend with row-table kernels.

## Fix

`Registry::is_admitted(name)` (`crates/intarsia-core/src/registry.rs:347`) reports admission the way `select` counts it (a row-table kernel by the kernel it twins, any
other kernel by its own state); `plan.rs:579` uses it for `PlanOp::admitted`. Reporting only: `select`, `admit`, the kernels the plan resolves, scratch, and
what `serve` may select are untouched, so no kernel changes for the 27B or the 35B at serve time. The only change to a plan description is that a row-table
twin whose base is admitted now says `admitted: true` (a twin of a rejected or untested base still says false).

## Tests

* `registry::tests::is_admitted_counts_a_row_table_twin_by_its_base` (core, host logic): untested -> false, base admitted -> twin true, base rejected -> twin false,
  a `rows_exact` kernel stands on its own state.
* `kernels::tests::the_27b_row_table_attention_is_admitted_through_its_base` (HIP crate, host logic over the real registration table): the 24 / 4 / 256 shape is
  accepted by `attn_decode_bf16_splitkv_rows` at m = 1..=16 and by its base; the solo pick is `attn_decode_bf16_splitkv`; with the base admitted the twin
  counts as admitted.
* `cargo test --release -p intarsia-core --lib`: 205 passed (2 ignored). `cargo test --release -p intarsia-backend-hip --lib`: 31 passed, including
  `round4_selection_is_pinned`, `round5_attention_selection_is_pinned`, `phase1_fold_selection_is_pinned`, `phase2_fold_selection_is_pinned`,
  `fp8_selection_is_pinned`, `wmma_fp8_selection_is_pinned`, `mxfp4_selection_is_pinned`, `moe_experts_selection_is_pinned` (the 35B's and 27B's selection pins).
