## 2. tp=2 accuracy (one GB10, both ranks, host communicator)

**Why one box stands for two.** A sum of two operands commutes, so NCCL's sum and the host comm's are the same bits. The
cross-host smoke checks this directly (section 3).

### KL21 against vLLM (the floor)

| | 35b-short | 35b-long |
|---|---|---|
| base tp=1 | 5.43e-3 PASS | 4.58e-2 FAIL |
| dev tp=2 | 6.27e-3 PASS | 4.27e-2 FAIL |

The 35b-long floor FAIL is pre-existing: base fails it identically. It comes from the chat_reuse_4k user-turn rows,
see [m3 accuracy debt](2026-10-21-m3-accuracy-debt.md). tp=2 is not worse than tp=1 on either set.

### Self-golden against base tp=1 (S1): TP noise vs the 35B's own tp=1 reordering noise

Mean KL21 for prefill / decode, then flip %.

| configuration | 35b-short | 35b-long |
|---|---|---|
| base against itself | 2.7e-13 / 3.7e-11, 0 | 2.8e-13 / 1.1e-11, 0 |
| tp=1, SIMT attention (split-KV and flash disabled) | 4.0e-3 / 9.0e-3, 1.18 % | 2.83e-2 / 1.00e-2, 4.36 % |
| tp=1, fp8 GEMV disabled (decode only) | 0 / 3.8e-3, 1.88 % | 0 / 2.6e-3, 3.75 % |
| tp=1, nvfp4 GEMV disabled (decode only) | 0 / 4.9e-3, 0 % | 0 / 2.9e-3, 2.5 % |
| **tp=2** | **5.1e-3 / 1.24e-2, 1.32 %** | **3.22e-2 / 8.4e-3, 4.64 %** |
| tp=2 + 1 % bug on rank 1 (`INTARSIA_TP_TEST_BUG=scale:1.01`) | 4.8e-3 / 7.5e-3, 1.25 % | 2.97e-2 / 8.1e-3, 4.32 % |

**Findings**

1. **tp=2 sits inside the 35B's own tp=1 reordering spread.** Swapping only the attention kernels at tp=1 moves the 35B
   as far as tp=2 does:
   - short set: 0.8-1.4× in mean KL;
   - long prefill: 0.88×;
   - long flips: 4.36 % vs 4.64 %.
2. **The 8B-derived TP budget does not apply to the 35B.** That budget (mean 1.2e-3, max position 9.8e-2, flips 0.84 %)
   fails every tp=1 variant here, too. The 35B is 4-bit with top-8 routing, so one routing flip moves a position a lot.
3. **The same derivation on the 35B passes tp=2.** Taking the max over the tp=1 variants × k = 2 gives:

   | | 35b-short | 35b-long |
   |---|---|---|
   | prefill mean KL | 8.0e-3 | 5.7e-2 |
   | decode mean KL | 1.8e-2 | 2.0e-2 |
   | flips | 3.8 % | 8.7 % |

   tp=2 passes all of these.
4. **The 1 % partial-scale bug is invisible on the GPU** at the 35B's noise level. The 8B gave the same answer
   (docs/accuracy.md). No GPU self-golden budget can separate it.
5. **What does catch the bug is the Mac f32 test,** `tp_hybrid::hybrid_moe_tp2_catches_a_one_percent_partial_scale_bug`.
   It runs the same sharding code: GDN by k-head group, MoE inside each expert, FP8 and NVFP4 slices.
   - Clean tp=2 vs tp=1: 3.4e-6 rel L2.
   - With the bug: 5.3e-1.
   - That is a separation of 150 000×.
   - Default budgets and gate code are unchanged. The 35B TP budget above is measured, not shipped (same policy as the 8B).

### 256 greedy ids (chat template, corpus_docs prompt), first divergence from tp=1

| prompt | tp=2 | tp=1 SIMT attention (reference reordering) |
|---|---|---|
| 1497 tokens | 14 | 74 |
| 16026 tokens | 61 | 34 |

kernel swap.
