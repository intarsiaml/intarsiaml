## Friction list (draft)

Engine / tooling (fixed on this branch marked F):

1. F: `recipe new` classified the MXFP4 tensors as `unknown(weight_scale next to a U8 weight)` and refused Quark's
   `quant_method = "quark"`.
2. F: `recipe new` picked the closest recipe by tensor-template overlap (`qwen3_5_moe`, another family) and took the
   model-level fields from it, so `norm_offset` (zero-centred RMSNorm) and the parsers became TODOs although
   `qwen3_5` is this model's own family. Now taken from a same-family recipe.
3. F: `recipe new`'s default output is `recipes/<family>.toml`, which here is the family's existing recipe; the error
   told the user to pass `--force`, i.e. overwrite another model's recipe.
4. Recipes have no prefix parameter or inheritance: the VL wrapper needs a full copy of `qwen3_5.toml` with
   `model.language_model.` prefixed (`recipes/qwen3_5_vl.toml`).
5. F: the dense FFN block loaded bf16 only; a quantised dense FFN failed in `plan` with "tensor ... has shape
   [17408, 2560], expected [17408, 5120]" (the packed fp4 width), which does not say "quantised FFN unsupported".
6. No golden obtainable through the documented paths: radiance ignores `prompt_logprobs`; no bf16 base on the fleet;
   `tools/golden.py` loads the full model (54 GB bf16) and needs amd-quark, whose `quark.torch` import needs scipy and
   more; `--make-golden-max-gb 5`. F (tool): `tools/golden_quark_mxfp4.py`.
7. `qualify --resume` keeps FAIL stages (and what they blocked): after the FFN fix a new `--out` was needed. Documented.
8. Metal has no GatedDeltaNet or quantised-matmul kernels: no Qwen3.5-family model runs on Metal. The CPU backend's
   quant and GDN ops are f64 references: a 27B CPU smoke test is ~30 GB and very slow, so the "cpu first" fallback in
   the docs does not work for this model.
9. MXFP4 refuses to shard (TP=1 only on intarsia; radiance runs TP=2).
10. `output_gate_type: "swish"` in the config is read by neither HF transformers 5.19 nor intarsia (both use a sigmoid
    gate). Unverified risk.

Fleet / process:

11. Finding the original checkpoint: radiance serves a converted `.rad`; the HF original was found only through unanimis
    (`unim recall`) and radiance's HF cache. The two other 27B checkpoints on the fleet (RadixArk NVFP4 = mixed NVFP4
    W4A4 + FP8, unsupported; unsloth GGUF) are not usable.
12. The fleetq guard blocks starting the radiance unit unless `FLEETQ_JOB` is set on the command itself.
13. `deploy/tatooine/dev.sh` has no host networking, so a server in it is unreachable for localeval: a separate
    `docker run --network host` was needed.
14. Slot contention: every GPU step waited behind G2/M3 windows; the CPU goldens waited behind exclusive Metal benchmarks
    on endor.
15. macOS rsync has no `--info=progress2` (first copy attempt failed); 19.8 GB tatooine -> endor took ~11 min (~30 MB/s).
16. localeval's unanimis capture failed (ssh mux refused) for the intarsia speed run.
