Based on the provided source code, here is a detailed technical overview of the `intarsia` inference engine’s core architecture, focusing on the admission testing harness and the backend abstraction layer.

### 1. High-Level Architecture

The engine is built around a **Backend Abstraction** (`backend.rs`) that decouples the execution of operations (kernels) from the specific hardware (CPU, CUDA, HIP, Metal). A **Registry** (referenced but not fully shown, implied by `registry.rs` imports) manages which kernel implementations are available for each operation and hardware architecture.

The `admission.rs` module serves as the **Quality Assurance and Selection Harness**. It does not run inference for production; rather, it runs a suite of "admission tests" to verify that a candidate backend's kernels produce results that match a reference implementation within defined tolerances. Only kernels that pass these tests are marked as `Admitted` and become selectable by the engine for actual inference.

### 2. Key Modules and Components

#### A. `admission.rs`: The Testing and Selection Harness

This module is responsible for generating test cases, running them on both a reference backend and a candidate backend, comparing the results, and updating the registry's admission status.

**1. Configuration and Test Case Generation**
*   **`SweepConfig`**: Defines the dimensions of the test sweep (e.g., `hidden`, `n_heads`, `vocab`). It defaults to Qwen3-0.6B-like shapes. It supports a `quick` mode for faster, smaller tests.
*   **`sweep(op, cfg)`**: The core generator. Given an `Op` (e.g., `Matmul`, `AttnDecode`, `RmsNorm`), it generates a `Vec<Case>`.
    *   It uses a deterministic `SplitMix64` RNG seeded by the op and config to ensure reproducibility.
    *   It creates `HostCall` objects, which describe the operation, input tensors (`HostTensor`), output specifications (`OutSpec`), and attributes (`OpAttrs`).
    *   **Specialized Sweeps**: For complex ops like `GdnDeltaRule` (Gated Delta Net), `ShortConv`, or `AttnDecode` with sliding windows, dedicated helper functions (`gdn_sweep`, `short_conv_sweep`, etc.) generate specific edge cases (e.g., chunk boundaries, zero vs. non-zero initial states, specific window sizes).
    *   **Quantization/MoE**: It delegates to `crate::quant::cases::sweep` for quantized weights and MoE ops, ensuring format-aware data generation.

**2. Execution and Comparison**
*   **`run_admission(reference, candidate, opts)`**: The main entry point.
    *   Iterates through all kernels registered by the `candidate` backend.
    *   Filters kernels by architecture (`arch_matches`) and optional filters (`only_ops`, `only_kernel`).
    *   For each kernel, it finds the corresponding `is_reference` kernel in the `reference` backend.
    *   For each test case generated by `sweep()`:
        1.  Checks if the kernel's shape predicate (`kern.accepts`) matches the case's shape.
        2.  Runs the case on the **reference** backend (`run_host`).
        3.  Runs the case on the **candidate** backend (`run_host`).
        4.  Compares the outputs using `compare()`.
*   **`compare(cand, refr)`**:
    *   For **Integer** outputs (e.g., `Argmax`, `Sample`): Requires exact match (`mism == 0`).
    *   For **Floating Point** outputs:
        *   Calculates `max_abs` (scaled by the reference's max magnitude to handle different scales).
        *   Calculates `rel_l2` (Relative L2 norm).
        *   Checks for non-finite values (NaN/Inf) which cause immediate failure.
    *   Returns `(scaled_max_abs, rel_l2, is_finite_and_matching)`.
*   **`judge(kern, got, want)`**: A helper that applies the kernel's specific tolerance (`tol_for`) to the comparison results to determine pass/fail.

**3. Reporting and Registry Update**
*   **`AdmissionReport`**: Contains `AdmissionRow` (per-case results) and `KernelSummary` (aggregated results per kernel).
*   **`apply(reg)`**: Updates the `Registry`.
    *   If a kernel has 0 cases: `Admission::Untested`.
    *   If all cases pass: `Admission::Admitted`.
    *   If any case fails: `Admission::Rejected`.
