# Tensor parallelism on both R9700s: the gate against tp=1, and what was built on top (lane tp2, 2026-10-25)

Qwen3.6-35B-A3B NVFP4 (and Qwen3-8B, Qwen3.8-27B MXFP4) on tatooine's two R9700s (gfx1201), `intarsia ... --backend hip --tp 2
--devices 0,1`: one process, two in-process ranks, HIP P2P all-reduce. Radiance was down for each window (`raw/downtime.log`).
Raw logs: `docs/results/2026-10-25-tp2-hip/raw/`.

## 0. What was already true on main

The brief said fusion at tp=2 is opt-in. It is not: `tp_fusion(env, "hip", tp)` has been on for HIP at `--tp 2` since lane HS
(`a7336525`, LOG 2026-10-21 19:50, user decision to soak and flip). `INTARSIA_TP_FUSION=0` opts out. So the "tp=2 with
fusion" arm is what main ships, and the "without fusion" arm (-5 to -12 % decode, `2026-10-21-h1-tp2-hip.md`) is the opt-out.
This lane's stage 1 therefore changes the rule to "HIP and `--tp` > 1" (the same behaviour: the HIP collective is two ranks) and
adds the gate the user chose on 2026-10-25.

## 1. The tp gate

### Decisions

1. User, 2026-10-25 01:00 ("Gate vs tp1"): the gate is the KL change against our own tp=1 output within the noise envelope; fusion is
   default-on at tp>1.
2. Coordinator, 2026-10-25, after the first result below (LOG.md): the tp2-vs-tp1 KL cannot separate a 0.3 % partial-scale bug from
   reduction-order noise, so the gate for HIP tp>1 is now
   1. the comm and sharding mutants are killed, including the 0.3 % partial-scale mutant, through a DIRECT check (per-rank partial sums
      or the all-reduce output against tp1, tolerance derived from fp32 reduction-order bounds), not KL;
   2. tp=2 run-to-run 256 ids identical;
   3. KL(tp2 vs vLLM) <= KL(tp1 vs vLLM) x 1.02 on the mean and x 1.10 per prompt (numbers fixed before further data);
   4. KL(tp2 vs tp1) is reported, not gating. `tp_ref_noise_factor` stays unset.
   If the 0.3 % mutant does not fail check 3, check 1 carries it alone.
   Release blocker: no tp>1 default change and no un-draft of #140 until the 0x1016 crash (section 6) is explained or at 0 in 12 runs.
   The HIP 1.66x vs CUDA 1.10x gap is a follow-up.

Mechanism that exists: recipe key `[accuracy] tp_ref_noise_factor` and `refnoise::resolve_factor_tp` (PR #146) for the report-only form of
check 4; `scripts/tp2-hip/tp-gate.py` for check 3; `crates/intarsia-models/tests/tp_test_bug.rs` and
`crates/intarsia-backend-hip/tests/tp_partial_sum.rs` for check 1 (lane branch `lane-tp2/direct`).

### Check 4 (reported): tp=2 vs tp=1, short golden, the same build

`raw/w1/self-tp2-vs-tp1-short*.out`, verdict `verdict-gate-short.json`; reference noise 3.161e-3 (vLLM re-run, 1441 positions):

| run | prefill mean KL21 | decode mean KL21 | prompt `code`, KL / (3 x its noise), prefill, decode |
|---|---|---|---|
| tp=2 vs tp=1 | 5.261e-3 = **1.66x** the noise | 4.108e-3 = 1.30x | 1.505, 1.121 |
| tp=2 + `scale:1.003` on rank 1's partials vs tp=1 | 4.471e-3 | 4.854e-3 | 1.046, 1.313 |
| tp=2 + `scale:1.01` vs tp=1 | 4.671e-3 | 8.013e-3 | 1.391, 4.231 |

The same number H1 measured on 2026-10-21 (1.664x, `code` 1.51x); CUDA tp=2 vs tp=1 was 1.10x. An 0.3 % partial-scale bug scores a lower
prefill KL than clean tp=2, hence decision 2.

### Check 3 (gating): distance to vLLM, existing single runs

`scripts/tp2-hip/tp-gate.py --ref raw/w1/acc-tp1-batch-35b-short.out --cand raw/vocab/acc-tp2-on-35b-short.out` (tp=2 runs are bitwise
run to run, so one run is the run):

- **Mean: PASS.** Prefill 5.967e-3 vs 5.978e-3 (ratio 0.998, limit 1.02); decode 7.102e-3 vs 12.14e-3 (0.585).
- **Per prompt (cap 1.10): FAIL on 9 of 20 cells.** Prefill: `code` 1.60, `chat_system` 1.30, `chat_multiturn` 1.94, `chat_reasoning` 1.69 (`count` is 1.099,
  just inside). Decode (16 scored positions per prompt): `count` 1.25, `chat_short` 2.19, `chat_system` 1.53, `long_prose_300` 5.28,
  `long_prose_700` 1.20. The other cells are well below 1 (down to 0.21), so the per-prompt ratio scatters on both sides of 1 by far more
  than 10 %. The window w8 adds two equally valid tp=1 variants (no fusion; chunk 233) scored against the tp=1 reference the same way,
  to show how much of that scatter is not tp (section 6).
