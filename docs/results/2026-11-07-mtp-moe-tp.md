## Status

In progress (design written 2026-11-07 00:05 EST, before any code).

## Design

### What blocks it today

1. `mtp::load_head` refuses an MoE head at tp > 1: the rank's `dims.moe` is the halved per-rank config (I = 256), so the
   head's fused bf16 experts (`[E, 2*512, H]`) cannot load against it, and the head path has no reduce after its MoE.
2. The Sparks run tp2 **across processes** (`--tp-remote` on spark1, `intarsia tp-worker` on spark2, NCCL over CX-7). Every
   piece of speculation refuses or ignores a remote rank: the loader refuses `--spec mtp` for `Group::Remote`
   (`load.rs` ~471), `Model::enable_verify` refuses `remote`, `forward_verify_run` only knows in-process peers,
   `SequenceState::spec_rollback` returns `Unsupported` for a remote rank, and `RankModel for Model` has no `verify_rank`.

So the work is "MoE head under TP" plus "speculative verify + rollback over the `tp_remote` protocol".

### Options considered

| option | head collectives per head pass | remote rank during a drafting round | drafts vs tp1 |
|---|---|---|---|
| A. shard the head like the trunk (attention by heads, experts inside each expert, lockstep all-reduces) | 2 (attention o, MoE) over the wire | runs every head pass (new `FWD_DRAFT` for `Model`, its own copy of the draft lm_head for the chained ids, `active` flag sync) | not bitwise (bf16 MoE reduce rounds twice) |
| C. shard attention (lane dfh path), replicate the MoE | 1 (attention o) | as A | not bitwise |
| **B. whole head on rank 0 only** (chosen) | **0** | **idle** (never sees the head) | **bitwise** the tp1 head's, given the same hidden row and the same kernels |

### Chosen: B, the whole head on rank 0

- Rank 0 loads the head unsharded against the **global** dims (q/k/v/o and fc unsliced, the MoE with the full
  `MoeConfig`: I = 512, shared I = 512, routed experts quantised from bf16 exactly as at tp1). Peers (in-process or remote)
  load no head and keep no head state. Opt-in only: it exists only with `--spec mtp` and an MoE head at tp > 1; the dense
  27B lane-dfh lockstep path is untouched.
- The head's input is the trunk's final normed hidden row, which is replicated on every rank after the last all-reduce, so
  rank 0 has everything it needs. The head runs with a "whole" switch (an atomic like `head_rows_attn`) that makes the
  attention helpers (`attn_bufs`, `attn_project`, `gate_qkv_call_at`, `attn_rows_core`, `attn_out_proj`) read the global dims
  instead of `ldims` and skip the o-projection reduce; the MoE gets its own `MoeScratch` (full I). Head passes are capped
  at `max_tokens / world` rows so the shared activation buffers (sized for the rank's share at `max_tokens` rows) hold
  them; the head's KV cache holds all KV heads. `mtp_dry_run` records the head in the same mode, so plan resolution,
  admission and scratch sizing cover its full-width shapes.
- Drafting is rank-0-local (`DraftLink::Solo`), so a drafting round never touches NCCL or the TCP link.
- Remote protocol (version bump): `FWD_VERIFY` for `Model` (rank 1 runs `verify_peer`: row-exact kernels, per-row
  GatedDeltaNet saves), and a speculative rollback that rides on the next command (`FWD_ROLLBACK` flag + keep length in the
  forward/verify body; a sync `T_SPEC_ROLLBACK` when a truncate or snapshot comes first). The worker loads with the same
  `LoadOptions` as rank 0 (the handshake fingerprint checks it), enables its verify rows and prefers per-row verify
  attention as rank 0 does, so its verify pass is bitwise its decode step per row.
- Sampled speculation stays single-rank (as for in-process peers): a sampled request at tp2 decodes plainly.

### Cost estimate (35B NVFP4, CUDA tp2 across the Sparks, k = 2)

- Head per round: what tp1 pays (catch-up pass over the accepted rows + 1 chained pass, each with a full-vocab argmax
  over the NVFP4 lm_head, ~286 MB read per draft), on rank 0 alone, **no collective, no TCP message**. Rank 1 idles.
  Option A/C would add 2-4 cross-host all-reduces per round plus a remote lm_head copy (~0.3 GB) and its GEMV.
- Rollback: 0 extra round trips (piggybacked).
- Verify: one 3-row pass at tp2, **eager** (the captured spec step and the verify graph are single-rank / HIP only), with
  the trunk's 80 all-reduces. This is the term that decides rule (b); a verify graph at tp2 is follow-up work, not this lane.
- Memory: rank 0 +~0.5 GB (head attention bf16 + 256 NVFP4 experts + shared expert + its KV + MoE scratch); rank 1 + the
  per-row recurrent copies of a verify pass.
