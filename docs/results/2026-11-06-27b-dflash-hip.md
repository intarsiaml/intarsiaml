## Item 0: `serve --spec dflash` at tp2 fails long requests (bug)

**Symptom** (w1, `raw/w1/suite-dfl7-speed-plain.log` on the sibling branch): `no kernel for attn_decode on hip/gfx1201 (m=1 n=0 k=128 act=Some(Bf16)
w=Some(Bf16)) [admitted kernels only]`, on the suite's warm-up requests; the category files ran.

**Cause.** Not zero context keys: `n=0` is a `ShapeInfo` field attention never sets (it prints 0 for every attention call), and a draft row always sees
its block's keys. The 27B draft (`z-lab/Qwen3.8-27B-DFlash2`) has a 2048-key sliding window; once a request's context passes ~2.05k tokens its block
rows attend with `OpAttrs::window > 0`, which on HIP only the `.ext()` kernel `attn_decode_bf16_window` takes. `serve` selects admitted kernels only,
and admission covers the kernels the plan selects. The plan's draft probe (`Model::dflash_dry_run`) ran at the start of the context only (8 rows,
no row windowed), so the window kernel was never planned, never admitted and not selectable under `serve`. `generate` (no admission rule) ran it, which
is why w1's 4k traces worked. Hypothesis, not yet confirmed: the suite's speed-plain filler runs 1k / 4k / 16k contexts, and the first request past ~2.05k tokens is the one
that failed twice (the cells directory of the failed run is empty, so the failing request's size is not on record). w1's serve smoke confirms or
refutes it: the same suite cell on main's CLI (`dfl7-base`) must fail the same way, on the branch it must not.

**Fix** (`crates/intarsia-core/src/model/dflash.rs`): the draft dry run also records a draft at the end of the context when the context can outgrow the
window, so the windowed calls are planned and admitted. Regression test `dflash2_plan_covers_the_windowed_draft_and_serves_past_the_window`
(`tests/dflash2_cpu.rs`, draft window 13 > two blocks, as the 27B's): the plan must hold a windowed `attn_decode` call (fails without the fix: planted by
disabling the second probe), and with admission on and admitted kernels only, a 1-token prompt and one 3x past the window decode `--spec off`'s ids.
The cpu test does not reproduce the serve error itself (the cpu attention kernel serves windowed and plain calls under one admitted name); the HIP gate
is the window below.

**CPU and CUDA.** CPU: one attention kernel takes both, so serve never failed there; the plan change is shared. CUDA: DFlash2 drafts are refused at load
(`DynConv` is cpu and HIP only, `crates/intarsia-backend-cuda/src/kernels.rs`), and its windowed attention kernels (`attn_decode_bf16_ext`,
`attn_decode_bf16_splitkv_ext`) take D=128 anyway. A zero-key draft row cannot happen on any backend (the block's own keys are always in range).

**Rule (pre-registered).** With the branch binary, `serve --spec dflash --spec-k 7 --tp 2` loads, its plan lists `attn_decode_bf16_window` and admission
admits it, and the localeval suite cells `speed-plain` and `speed-spec` run to the end (exit 0, or 3 for a spread rejection; never 2, a harness error);
main's binary on the same cell is the negative control. `plan show` (json and text) for the 27B `--spec off` and `--spec mtp --spec-k 2`, the 35B tp2
off and MTP k2, and the 8B tp1 off is identical against main's binary; `kernels test --backend hip --quick` passes. Speed: the dry-run change cannot
touch a pass, so the branch with knobs unset (A) must not be slower than main's binary (Z): runs Z A Z A, mean pass ms of A <= Z's + 0.3 ms at both
prompts; greedy ids of A and Z equal `--spec off`.

## Item 1: the DFlash2 draft split over both ranks (`INTARSIA_DFLASH_TP=1`, default off)

**What changed.** `LoadOptions::dflash_tp` (`INTARSIA_DFLASH_TP`): every rank loads its part of the draft: q / k / v / gate / up by output rows (16 of
32 q heads, 4 of 8 kv heads, 8704 of 17408 ffn columns per rank), o / down by input columns with their partial sums all-reduced (2 all-reduces a draft
layer, 10 a draft); norms, the conv kernel projections and base kernels, `fc` and the context norm replicated (the context ingest needs no collective,
each rank ingests its own kv heads after its own pass). With a vocab-parallel head (the 27B's at tp2) each rank takes the drafts' logits on its
vocabulary shard of the group's head (no whole-head copy on rank 0 any more: -1.3 GB with the fp8 head), its top `top_k` per row on the host, and sends
them to rank 0, which merges them (the merge equals the whole row's top-k, ties in index order) and runs the selector. Rank 0 alone holds the selector.
Without a vocab-parallel head rank 0 takes the logits on its whole head as before. `--spec mtp` and `--spec off` paths are untouched.

Checks (cpu, two in-process ranks, `tests/dflash2_cpu.rs`): `dflash2_split_draft_drafts_equal_the_whole_draft` (the split draft's drafts equal the whole
draft's at 8 context lengths from 1 to 40 tokens, window 6, with and without a selector, both head layouts; catches 2 of 2 planted faults: the merge
not sorting, the column shard taking rank 0's columns), `dflash2_split_draft_greedy_ids_equal_spec_off` (random and scripted drafts, every acceptance
pattern, both head layouts).

**Rule (pre-registered, written before any measurement).** Same binary, tatooine tp2, A = `INTARSIA_DFLASH_TP` unset, B = `1`.

* Trace: `generate --spec dflash --spec-k 7`, `INTARSIA_SPEC_TRACE=1`, 256 tokens, prompts short-0 and 4k-1, mean of the passes after the first 4, runs in
  the order A B A B. Pays if, on the mean of the two runs per arm, B's draft ms <= 0.70 x A's at both prompts **and** B's pass ms <= A's - 3.0 ms at
  both prompts.
* Categories: a fresh `serve --spec dflash --spec-k 7` per visit, visits A B A B (two rounds, the same order), the 7 category files, 512 forced tokens.
  **Ship as opt-in** (default stays off; a flip is the user's call) if B / A of the per-category means is >= 1.10 in at least 5 of 7 categories and
  >= 1.00 in all 7, **and** tokens a pass differ by <= 0.15 between A and B in every category (a split draft must not lose acceptance).
* Lossless: greedy ids with B equal `--spec off` at short-0 and 4k-1 (tp2).
* No change elsewhere: knob unset, the same `plan show` as item 0's rule (27B off and MTP k2 unchanged against main's binary).
* If the draft ms does not pay (block ms not down by >= 30 %), stop the item and record why.

**Windows.** w1 (`PRE=w1`, `scripts/dh/stages-w1.sh`, then serve arms `dfl7-base dfl7 dfl7-on dfl7-on2` with the suite cells): items 0-2 traces
and every gate. w2 (`PRE=w2`, `scripts/dh/stages-w2.sh`): item 3. Category ABAB windows only for items whose trace rule passed.

## Item 2: device-side top-k for the draft's candidates (`INTARSIA_DFLASH_DEVICE_TOPK=1`, default off)

**What changed.** The draft's per-row candidates (the selector's top 16, or the argmax without a selector) are taken with the backend's existing device
top-k (`Backend::topk_rows`, lane htk's `ik_topk_f32`: value descending, ties by ascending index, the order of the host's `row_topk`), so a rank downloads
16 values and ids a row instead of the row's logits (split draft: 0.5 MB a row of its shard; whole draft: 1 MB a row) and skips the host scan. A row
the kernel flags for a NaN, and a backend without the kernel (cpu), take the host path. The selector itself stays on the host: 16 candidates x rank 256
x 7 rows is microseconds. `INTARSIA_DFLASH_DEVICE_TOPK=check` runs the device top-k and the host's on the same logits and prints every differing row
(`dflash2 topk check`), the GPU gate of the device candidates. Works with the whole draft and the split one.

**Rule (pre-registered, before any measurement).** Same binary, item 1 on in both arms: B = `INTARSIA_DFLASH_TP=1`, C = B + `INTARSIA_DFLASH_DEVICE_TOPK=1`,
traced as item 1 (short-0 and 4k-1, runs B C B C).

* Pays if C's dl + select ms <= 0.5 x B's **and** C's pass ms <= B's - 0.4 ms, at both prompts (means of the two runs per arm).
* Gate: one `check` run at each prompt with zero differing rows; greedy ids with C equal `--spec off`.
* If the categories window has room for C visits: no category below 0.98 of B, tokens a pass within 0.15 of B.
* Stop rule: if item 1 leaves B's dl + select under 0.6 ms a pass, item 2 cannot meet its rule; it stops there and the reason is recorded.

## Item 3: the verify pass (why 8 rows cost 25 ms against an 18 ms one-row step)

**Known before this lane** (lane vrc, `docs/results/2026-10-28-vrc-hip-verify-cost.md`; lane vat): the per-row GDN loop was already replaced by one
snapshotting launch (-3.3 ms at 8 rows) and the verify attention by one row-table launch per layer. VRC's microbench of the W4A8 GEMV
(`tests/verify_gemv_bench.rs`) puts M = 8 at 1.18-1.72x of M = 1 per shape, about 3.2 ms a pass summed over the 64 layers (48 GDN x ~49 us + 16
attention x ~54 us): the largest single piece. VRC found the kernel bound by its per-row dot work, not by loads (a 4-weight-row form was slower).
New here: an 8-row f32 partial is 8 x 5120 x 4 = 160 KiB, above the tagged-line (LL) all-reduce limit (`LL_MAX_DEFAULT` 128 KiB in `comm.rs`; 7 rows
are 140 KiB), so the 7- and 8-row verify all-reduces (129 a pass) take the fence path, which the comm notes measure at ~1.7x the LL time at these sizes.

**Candidates** (both bitwise by construction, both knobs default off):

* 3a: `INTARSIA_HIP_AR_LL_MAX=262144` (an existing knob, no code): the 7- and 8-row verify all-reduces on the LL path. A world-2 sum is `a + b` on
  either path (bitwise equal, `tests/comm.rs`).
* 3b: `INTARSIA_HIP_A8_ILP=2|4` (`kernels/hip/mxfp4_a8.hip`): the W4A8 rows kernel for M >= 2 puts its scheduler barrier every 2 or 4 activation
  rows instead of every row, so the dot chains of 2-4 rows can overlap (the kernel issues one dependent `v_dot4` chain per (weight row, activation row);
  with one row between barriers only the 2 weight rows' chains are in flight). Each chain keeps its instructions and order, so outputs are bitwise.
  M = 1 (the decode step, the fused kernel) is untouched.

**Rule (pre-registered, before any measurement).**

* 3b kernel gates first (GPU, w1): `tests/mxfp4_a8.rs`, `tests/mxfp4_a8_fuse.rs` and `tests/rows_exact.rs` pass with `INTARSIA_HIP_A8_ILP=2` and
  `=4`, and `mxfp4_a8_fuse`'s `FUSEHASH` (every output byte of 512 launches, M 1..16) equals the unset run's and the pinned `fac47447935a8383`. If
  either fails, the E / F arms are dropped from w2 (`ILPS`) and 3b stops; `VRC_BENCH=1 tests/verify_gemv_bench.rs` at ILP 1 / 2 / 4. 3b goes to the trace only if M = 8 is >= 5 % faster on
  the summed per-layer time of the bench's shapes.
* Trace, each candidate on top of the best of items 1-2 (arm C, or B if item 2 does not pay), runs X Y X Y at short-0 and 4k-1: pays if verify +
  rollback ms drops by >= 0.7 ms at both prompts (means of the two runs), greedy ids equal `--spec off`, and MTP k2's pass (3 rows, unchanged path
  for 3a: 60 KiB messages) is not slower by more than 0.3 ms.
* Categories, if the trace pays: visits X Y X Y, ship as opt-in if Y / X >= 1.02 in >= 5 of 7 categories, none below 0.99, tokens a pass within 0.05
  (a bitwise change keeps acceptance).
* Data for the rest of the item, same window: verify + rollback against rows (MTP k1..k6 at short-0), profiled op tables of off, dfl7 A and dfl7 C.
