# l5r7: z-fast launch order for the grouped MoE projections (35B prefill)

Branch `lane-l5r7/moe-zfast` (merged with origin/main 6b01ead74). Raw logs: `docs/results/2026-10-25-l5r7-moe-zfast/raw/{g1,g2,g3,ab}`.
Origin: the fp8 WMMA lane (docs/results/2026-10-25-l5-moe-fp8-wmma.md) found most of its 1.30x over r7 was launch order, not the kernel. This lane keeps only the launch order.

## Change
`kMwZFast` in `moe_wmma.h`, `moe_wmma_r7.h`, `moe.hip`: grid is (pair tile, feature tile, expert slot) instead of (slot, feature tile, pair tile), so the pair tiles of one expert run together and share its weights through the L2. Same arithmetic per output element, so the output is bit for bit the same. Default ON; `INTARSIA_HIP_MOE_ZFAST=0` restores the old order (docs/tuning.md).

## Served A/B (localeval speed, 35B, card 1, `--max-batch 1`, interleaved base/dev x3 visits, 3 reps each)
Prefill tok/s, mean of 9 reps per arm (per-visit values in raw/ab/v*.txt):

| prompt tokens | base | z-fast | prefill change | TTFT base -> z-fast |
|---|---|---|---|---|
| 512 | 4805 | 4896 | +1.9% | 0.101 -> 0.103 s |
| 2048 | 8833 | 9274 | +5.0% | 0.226 -> 0.217 s |
| 4096 | 9840 | 10336 | +5.0% | 0.416 -> 0.394 s |
| 16384 | 8731 | 9190 | +5.3% | 1.908 -> 1.812 s |

Consistency: at 16384 the per-visit means are base 8698/8780/8715, dev 9204/9177/9189 (every dev rep above every base rep). At 4096 the per-visit means are base 9592/10016/9912, dev 10383/10285/10341. Decode is not affected by the change; its numbers are noisy in this harness (spread 15 to 29% per visit, plus one implausible 5373 tok/s mean at 16384 base that comes from the harness output, not checked), so no decode claim is made. Stop rule was 3% served gain at 4k: met (5.0%).
