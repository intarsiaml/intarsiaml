# sideflip: `INTARSIA_SIDE_EAGER` default-on (CUDA), 2026-11-18

**Decision (user, 2026-11-18 08:20 EST):** make the capture-only side-stream forks of lane postchain2 the default.

## Change
- `crates/intarsia-core/src/model.rs` (`Model::side_fork`): eager passes no longer fork to the side stream unless `INTARSIA_SIDE_EAGER=1`. Before: forks unless `=0`. `=0` still means capture-only, so existing opt-in configs keep their behaviour.
- `CAPTURES_ACTIVE` is now a thread-local count instead of a process-global atomic (Fable review of #447, low: with a global count, an eager pass on another thread while any capture ran would still fork and re-enter the slow mode). A CUDA capture records on the thread that runs its body (`graph_capture` runs the closure synchronously), so captures still see their forks.
- Only the CUDA backend implements `stream_fork`, so HIP and Metal are unaffected.
- Fable's second #447 note (DSv4.1 capture has no guard) needs no change: the DSv4.1 runtime does not call `Model::side_fork`; its own lane forks are capture-only already.
