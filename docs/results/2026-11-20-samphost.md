# samphost: opt-in sampled verify pass without full-vocab D2H (2026-11-20)

## Brief

Lane `samphost`: remove most of the ~3.4 ms fixed host/D2H overhead per SAMPLED MTP verify pass on CUDA, opt-in, with seeded sampled output byte-identical. Worktree `.worktrees/samphost` (branch `samphost`, from origin/main eeca95f8e).

### Evidence
From `docs/results/2026-11-20-samp64.md` (nsys section, follow-up 2), spark2, 35B NVFP4, `serve --max-batch 2`, single stream:
- A sampled verify pass idles the GPU 3.2-3.7 ms against 0.8-1.0 ms for greedy.
- It makes 4.0 D2H copies of 4.0 MB per pass, against 1.3 copies of 1.3 MB for greedy: eager draft download, whole-vocab logits rows of the verify pass (3 x 248k floats = 3 MB), host draws.
- So sampled drafting gains only ~x1.25 at 4k where greedy gains x1.5.
- The two-stream pass already returns verify rows as top-k (`INTARSIA_VERIFY_TOPK`); the one-stream sampled pass does not.
- Seed-exactness design: `crates/intarsia-core/src/engine/keyed.rs` (one RNG value per generated token in order; a verify row holds the bits of the plain step's logits; a draft is kept only where the draw equals it).
- KV-once (#473) is default-on now, so re-baseline.

## Progress
- 17:00 Code read. The one-stream sampled pass is `Seq::keyed_finish` with `defer = false` (`busy` is `b > 1`, so a lone stream never defers): `Model::mtp_draft` (eager, drafts downloaded), then `Model::forward_verify_logits` (rows x 248k floats downloaded, 3 MB for 3 rows) and a host `Sampler::sample` per row (a 248k-key `select_nth` each for `top_k` 20). The two-stream batched pass already reads top-k rows (`INTARSIA_VERIFY_TOPK`, recipe-on for the 35B on CUDA), but its `n == 1` short-cut also took whole rows.
- Chosen: (a), top-k rows for that pass. `Sampler::sample_topk` is already exact against `sample` on the whole row (it is what plain batched steps with device-side sampling use). Not (b): reproducing the host's f64 normalisation bits on device is the risky part and buys little over (a). Requests with `top_k` 0 or above 64 keep whole rows (with `keep == n` the host's cut normalises over the whole row, so a truncated row would change its bits); the checkpoint's generation_config gives `top_k` 20 to requests that do not set it.
