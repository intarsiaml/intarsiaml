# samphost: opt-in sampled verify pass without full-vocab D2H (2026-11-20)

Lane `samphost`, branch `samphost` from origin/main `eeca95f8e`, 2026-11-20, spark2 (35B NVFP4, `serve --max-batch 2 --prefix-store on`, single stream, beside the untouched production vLLM), fleetq owner `claude-samphost`.

## Summary

1. **Attribution (before, KV-once default-on).** A one-stream sampled verify pass cost 21.2 ms at 4k against 18.2 ms for a greedy pass; the difference is host time (GPU idle 3.2 ms per pass against 1.0). Of it: ~0.85 ms is the host's whole-vocabulary selection for the draws (`Sampler::sample` over 248k logits per row), ~0.1 ms the 3 MB logits copy itself (cheap on GB10), and ~1.3 ms the eager draft + eager verify pass (their launches and the host round trip between them), where a greedy request replays draft and verify as one captured graph (`Model::spec_step`).
2. **Change (opt-in, default off): `INTARSIA_SAMPLED_VERIFY_FAST=1`.** A sampled request's own verify pass (i) runs as the greedy request's captured draft-and-verify step (`Model::spec_step_rows`) where that applies, and (ii) reads its rows back as the device-side top-k (`HeadMode::LastTopK` rows, `Sampler::sample_topk`) where the request's plain steps sample from top-k (`1 <= top_k <= 64`, e.g. the checkpoint default `top_k` 20), else as whole logits rows. Eager fallback (`Model::forward_verify_topk`) where the captured step does not apply. Both are exact: the replay is the eager pass bit for bit, and `sample_topk` draws the token the whole-row draw takes.
3. **Gate (ABBA none / fast / fast / none, one binary, 8 reps per window per cell, 16 per arm):** sampled T=0.7 **4k +18.3 % (2 SE 3.9 %), 32k +14.1 % (4.2 %), 64k +13.0 % (5.2 %)**; per-pass cost 21.9 -> 18.2 ms at 4k (= greedy's 18.1), 25.1 -> 21.3 at 32k, 28.6 -> 25.0 at 64k. **Seeded replies byte-identical** (T 0.7, top_p 0.95, 700 tokens, seeds 11 and 23, prompts 4.1k / 32.8k / 65.6k; all four windows, 6 of 6 in each). Greedy unchanged: pass cost 18.1-18.3 / 21.1-21.4 / 24.9-25.2 ms in all four windows; tok/s differences (+1.6 / -3.9 / +3.5 %, all inside 2 SE) follow the tokens per pass of the nonce'd prompts' text. No default flipped.

## Brief

Lane `samphost`: remove most of the ~3.4 ms fixed host/D2H overhead per SAMPLED MTP verify pass on CUDA, opt-in, with seeded sampled output byte-identical. Worktree `.worktrees/samphost` (branch `samphost`, from origin/main eeca95f8e).

### Evidence
From `docs/results/2026-11-20-samp64.md` (nsys section, follow-up 2), spark2, 35B NVFP4, `serve --max-batch 2`, single stream:
- A sampled verify pass idles the GPU 3.2-3.7 ms against 0.8-1.0 ms for greedy.
- It makes 4.0 D2H copies of 4.0 MB per pass, against 1.3 copies of 1.3 MB for greedy: eager draft download, whole-vocab logits rows of the verify pass (3 x 248k floats = 3 MB), host draws.
- So sampled drafting gains only ~x1.25 at 4k where greedy gains x1.5.
- The two-stream pass already returns verify rows as top-k (`INTARSIA_VERIFY_TOPK`); the one-stream sampled pass does not.
- Seed-exactness design: `crates/intarsia-core/src/engine/keyed.rs` (one RNG value per generated token in order; a verify row holds the bits of the plain step's logits; a draft is kept only where the draw equals it).
- KV-once (#473) is default-on now, so re-baseline.

## What changed

- `Model::forward_verify_topk` (eager solo verify pass, rows as top-k; `VerifyRead` read-back mode of `forward_verify_run`), `Model::spec_step_rows` (the captured `spec_step` with the rows read back, top-k or whole), both counting `intarsia_spec_verify_topk_solo_total` / `_fallback_total`; `intarsia_spec_keyed_graph_steps_total`.
- `Seq::keyed_draft` / `keyed_finish` (`engine/keyed.rs`): with the knob, the captured step where `spec_step_rows_ok` (one rank), else the eager pass with top-k rows where `Seq::verify_topk` allows. The batched verify pass's one-sequence short-cut takes `forward_verify_topk` for `LastTopK` rows under the knob. `INTARSIA_SPEC_TRACE` lines `spec: keyed draft`, `spec: keyed verify`, `spec: keyed graph step`.
- Knob: `BatchedOptions::sampled_verify_fast` (`INTARSIA_SAMPLED_VERIFY_FAST=1`) -> `Model::set_sampled_verify_fast` (copied to the decode twin). Startup line `batched MTP: a sampled request's own verify pass reads its rows back as the device-side top-k`.
- CPU: `CpuBackend::arc_topk()` (host reference of device top-k, `sampler::topk_row`), off by default; the test backend `RecCpu` forwards it.
- Scope of the hardware evidence: the seeded identity and the gate ran with the checkpoint's `top_k` 20, so every pass took top-k rows (fallback counter 0). Requests that read whole rows (`top_k` 0 or > 64, a stop-id mask in `min_tokens`) now also take the captured step under the knob; that combination is covered by the cpu test on `RecCpu` only. Two streams (the batched pass's one-sequence short-cut under the knob) were not measured on hardware.
- Not changed: the default (off), greedy requests, two-stream batched passes of several sequences (already top-k under the recipe's `verify_topk`), `top_k` 0 or > 64 requests (whole rows, now from the captured step where it applies).

## Follow-ups

- Default flip is the user's decision. A flip candidate: the 35B recipe's `[tuning.cuda]` (or the env default) after a two-stream check (the change only touches one-stream and one-sequence passes).
- `top_k` 0 requests keep whole rows; a provable-nucleus top-K would need the host normaliser's bits (with `keep == n` the cut normalises over the whole row), not attempted.
