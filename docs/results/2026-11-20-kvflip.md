## Part B: the flip and the review fixes folded in

- Review of #472 (Fable, nothing blocking), all four items done: (1) `tests/kv_once.rs`: a static `OVERRIDE` mutex held by every test that sets the process-wide override (the bitwise, the long-positions and the timing test), header no longer claims one test function; checked by running the binary with `KVONCE_TIMING=1` and no filter (3 tests, all pass). (2) `set_attn_kv_once_for_test` is `#[doc(hidden)]` with a doc comment saying it must never be called by the engine; I did not gate it behind a cargo feature (the integration tests live outside the crate, so a feature would need a self dev-dependency and CI flag changes for a hook that is a plain int store; the production path pays nothing: the fault int is 0 and is read only in the already-launched kernel preamble). (3) default flip as above, the tuning row documents `INTARSIA_ATTN_ROWS_PERSIST=0`. (4) new cases in `kv_once.rs`: wide launches of 20 / 33 / 64 rows (116 tables per shape), same-position rows (two mixed layouts), the captured graph on the fp8 cache (was skipped), caches of 132000 keys (`kv_once_long_positions_are_bit_identical`: 52 tables per shape, M 1..=16, positions 66000 to 131999, both bf16 shapes, rows against their solo launches). `kv_once` now takes 29 to 31 s knob-pinned (75 s with the cold first run on a shared GPU); `row_tables` ~70 s and passes with the knob unset, `=0`, `=1`.

## Coordinator addendum (Fable review of #472, nothing blocking): fold into part B

The review found nothing that blocks the flip; bit-identity holds by construction. Add to part B:
1. Test race: `crates/intarsia-backend-cuda/tests/kv_once.rs`. `timing_kv_once_layers` (~:375) also sets the process-wide override. With `KVONCE_TIMING=1` and no filter it runs in parallel with the bitwise test, which then risks a false pass or a false fail. Fix: a static Mutex that both tests hold, and remove the "one test function" claim in the header.
2. Fault hook in production: `set_attn_kv_once_for_test` (`crates/intarsia-backend-cuda/src/lib.rs:81`) is public non-test API, and `rows_stage1` (~:887) passes `g_kv_once_fault` into every knob-on launch, where captured graphs bake it in. Gate the setter behind a cargo feature or `#[doc(hidden)]` plus a test-only cfg that the tests can still reach. If a feature is cleanest, enable it in the test target. Keep zero cost on the production path. If this gets invasive, at least hide it with `#[doc(hidden)]` and say so.
3. Flip mechanics: `kv_once_mode()` (lib.rs ~:783-789) turns on only for exactly `1`/`2`. Make unset mean on, and keep `0` meaning off. Document in the tuning row that `INTARSIA_ATTN_ROWS_PERSIST=0` also disables it.
