## Part 1: why the test fails

The test (A = `prompt-4096.txt`, 4096 tokens; B = A + " Summarize the above in one paragraph.", 4105 tokens; one engine runs A then B,
greedy, 64 tokens, compared to a fresh engine's B) is lane hrr's gate for the strict rule. Lane hrr's own record says so
(`docs/results/2026-10-29-hrr-hybrid-reuse.md`: "`engine_hybrid_reuse_equals_cold` is the gate"; B after A cached 0 = cold) and that the default
was then changed by the user to main's rule ("can give text that differs from a fresh server's", 2026-11-02): after that rework the test
was never run with a model under the default rule (its workspace run skipped it, `INTARSIA_PROBE_DIR` unset). So it fails on any backend
where pass shape changes bits: Metal reproduced exactly this with the default rule (`2026-10-29-hrr-hybrid-reuse/raw/probe-ab4096-default.txt`:
cached 4095, B differs from char 152). CUDA has no committed run of it.

Mechanism (single-sequence engine): A's prefill snapshots the recurrent state at `plen - 1` = 4095 (`[0, 4095)` + last token). The default
rule resumes B there (`restorable_len`), so warm B runs `[0, 4095) + [4095, 4104) + [4104]` where cold B runs `[0, 4096) + [4096, 4104) + [4104]`.

### Measurements (`raw/w1/`, `hybrid_reuse_shapes` and the engine test)

Snapshot and restore are exact: "restored A snapshot + rest" equals "warm shape from a fresh state" bit for bit, with the chunked GDN delta rule
on and off. What differs is the pass shape. Warm B vs cold B, logits of the 8 rows of the last pass, the last token and 4 teacher-forced decode
steps (13 rows):

| GDN delta rule | warm vs cold: bitwise | max abs logit diff | KL max / mean (nats) | top-1 moved | engine test, default rule (64 greedy tokens) |
|---|---|---:|---|---|---|
| chunked (default since #378) | differs, 30 of 30 recurrent slots | 1.55 | 2.7e-2 / 8.3e-3 | 2 / 13 rows | **FAILS**, differs from cold at token 38 (`engine-any.err`, repeated in `engine-any-report.err`) |
| `INTARSIA_GDN_CHUNK=0` | **still differs**, recurrent slots 2.. differ | 1.60 | 5.8e-2 / 9.6e-3 | 0 / 13 rows | passes (`engine-any-gdn-off.err`): no flip within 64 tokens, by margin not by bits |

So the chunked kernel is not the cause (the hypothesis "chunk-shape-dependent GDN, default since #378" is **not** supported): turning it off
does not give cold's bits, only a flip that did not happen to land in 64 tokens. The pass-shape dependence is general, in the ops that feed the
recurrence (the same lane-hrr finding on Metal: the first differing slot depends on the split, the delta-rule recurrence itself is token-serial).
Any re-cut of cold B does the same: tail split 4+4, 3+5, 1+7, 2+3+3 (chunked GDN) gives KL max 4.5e-2 to 1.8e-1, top-1 moved 0-2 of 8-12 rows;
`[0,4094)+[4094,4096)+...` KL max 1.2e-1. Only a re-cut at a chunk cut (`[0,2048)+[2048,4096)+...`) is EQUAL to cold, in both columns.

Is the difference legitimate? The mean KL of 8e-3 to 1e-2 is the same size as this model's decode KL against the vLLM golden on the same
prompts (`acc-4k`: decode 8.7e-3, scored prefill 1.2e-2) and well inside the class floor (3e-2); an engine bug (wrong state) would move
KL by orders of magnitude, and the restore is bitwise exact. The cost is that greedy text can flip at a near-tie token (token 38 here),
which is what the strict rule exists to avoid.

### Strict rule (what the test gates), HIP

`INTARSIA_PREFIX_REUSE=exact` (`raw/w1/engine-exact.err`, `engine-exact-gdn-off.err`; the test sets it itself): PASS in both.

| request | cached tokens | tokens vs cold |
|---|---:|---|
| B after A | 0 | = cold |
| A after B | 0 | = cold |
| A repeated | 4095 | = cold |

Default rule for reference (`engine-any-report.err`): B after A 4095, differs at token 38; A after B 4095 = cold; A repeated 4095 = cold.

### The fix

`crates/intarsia-models/tests/hybrid_reuse_real.rs` only:
- `engine_hybrid_reuse_equals_cold` sets `INTARSIA_PREFIX_REUSE=exact` when the variable is unset and asserts what the strict rule promises
  (B after A = cold; A after B cached 0 = cold; A repeated 4095 = cold). With `INTARSIA_PREFIX_REUSE=any` it runs the default rule and prints the same
  lines without asserting (asserts again with `INTARSIA_PROBE_ASSERT=1`, which reproduces the original failure verbatim). A guard asserts the engine's
  `info().reuse_cold_cuts_only` equals the rule the run asked for: the rule is read once per process (`prefix_reuse_override`), so one rule per run.
- `compare` (shapes probe) prints KL and top-1 movement next to the max-abs differences.
- `docs/tuning.md`: the `INTARSIA_PROBE_ASSERT` row now says what it does for the engine test.

Not changed: the default rule, any engine code, any kernel. The weaker alternative (a tolerance on the default rule's tokens) was not taken: greedy
text over 64 tokens has no meaningful tolerance, and the strict-rule gate keeps the exactness claim intact.
