# mb-MTP on the R9700: 27B tp1, sampled speculation (2026-11-06)

**Result (27B, HIP tp1, MTP k=2, temperature 1.0, geomean over 7 categories):**

| mode | decode gain from mb | KL(mb law ‖ target) per token | total variation per token |
|---|---|---|---|
| `INTARSIA_SPEC_SAMPLED=match` (greedy drafts) | +11.3% | 0.099 nats | 0.072 |
| `INTARSIA_SPEC_SAMPLED=reject` (sampled drafts) | +5.9% | 0.026 nats | 0.029 |
| `reject`, k=4 (see Depth and ratio) | ~+8% over exact k4 | 0.030 nats | 0.032 |
| `reject`, k=4, `INTARSIA_SPEC_MB_RATIO=2` | ~+6% over exact k4 | 0.019 nats | 0.021 |

mb-MTP (`INTARSIA_SPEC_MB=1`) is opt-in and off by default: it changes the output law. With greedy drafts it costs ~4x the
KL of sampled drafts: whenever the greedy draft is also the target's argmax, every replacement is at most as likely, so
the draft is always kept and that position decodes greedily. llamAmpere drafts by sampling (our `reject`); their 0.009
nats per token (depth 6, their model) is in the range of our 0.026, not of 0.099. Exact `reject` is itself 3-6% faster
than exact `match` on chat, prose and recall (code is mixed; different windows, so indicative).

## What mb-MTP is

Ported from llamAmpere v0.6 (`common/sampling.cpp`, `common_sampler_verify_pq`, "mode-biased MTP"). On a rejected draft
the replacement token is drawn as usual; if the target rates the draft at least as likely as that replacement,
`p(d) >= p(x)`, and neither is a stop or EOS token, the draft is kept and verification continues. Code:
`crates/intarsia-core/src/spec.rs` (`mb_from_env`, `accept_sampled`), stop set from `Seq::stop_ids` in `engine.rs`.

## KL (window mb4)

`INTARSIA_SPEC_MB_AUDIT=1` logs, per sampled pass, the KL(law ‖ target) and total variation of the exact token law of each
draft row that decided a token (`spec::mb_row_law`: given the greedy draft for `match`, marginal over the drafted token for
`reject`; checked by Monte Carlo against `accept_sampled` in `mb_row_law_matches_the_driver`), summed and divided by the
tokens emitted (bonus rows sample the target exactly and add 0). It is a per-position (local) divergence: the law at each
position given the text so far, not a sequence-level KL. KL(target ‖ mb law) is infinite (mb gives some tokens no mass).
fleetq #8893, radiance down 23:43:08-23:56:46, one round, both arms with the audit on (costs ~3% decode, so speed
comes from the windows without it). Tool: `tools/mb/kl.py mb4 mtp2-on3 mtp2-old`.

## Depth and ratio at k4 (windows mb5, mb6; `reject`, temperature 1.0)

**mb is worth about +4-6% at any depth in `reject` mode, and the ratio knob trades it away about linearly against KL.**
Depth itself matters more, and per category: exact k4 against exact k2 is +18-22% on code and -5-6% on prose.

Both windows are **one round in a fixed arm order** (2-8 requests per cell): per-category differences under ~5% are noise.
mb5: fleetq #8928, radiance down 00:47:33-01:13:25. mb6: fleetq #8942, radiance down 01:19:25-01:45:33.

| arm (reject, k4 unless noted) | geomean decode vs exact k4 | KL(law ‖ target) per token | TV per token |
|---|---|---|---|
| exact k4 | 0 (exact k2: -5.4%, from mb5 / mb6) | 0 | 0 |
| mb, ratio 1 (`INTARSIA_SPEC_MB_RATIO` unset) | +4.3% with the audit on; ~+8% without (audit costs 3.3% at k4; mb5 mb k4 / mb6 exact k4) | 0.030 nats | 0.032 |
| mb, ratio 2 | +3.1% (audit on) | 0.019 nats | 0.021 |
| mb, ratio 4 | +0.4% (audit on) | 0.010 nats | 0.012 |

KL per token rises only a little with depth at ratio 1 (0.026 at k2 to 0.030 at k4), less than the share of draft-decided
tokens would suggest, because deeper rows are reached less often. Per category (mb6, `tools/mb/kl.py mb6 ...`):

| arm | category | passes | emitted tokens | KL per token (nats) | TV per token | rescued per token |
|---|---|---|---|---|---|---|
| ratio 1 | **all** | 5877 | 18385 | **0.0296** | 0.0323 | 0.033 |
| ratio 2 | **all** | 5931 | 18383 | **0.0185** | 0.0213 | 0.021 |
| ratio 4 | **all** | 6068 | 18382 | **0.0097** | 0.0115 | 0.012 |

mb5 (reject, against exact k2): exact k3 +5.2%, mb k3 +11.4%, mb k4 +13.9% geomean. mb5 has no exact k4 arm; mb6's
exact k4 (+5.7% over mb5's exact k2, code +18-22%, prose -5-6%) splits the k4 gain into about +6% depth and +8% mb.

**Next lever, not built:** the best depth differs by category (code k4, prose k2). llamAmpere adapts the draft depth per
request (3-5, up after fully accepted drafts, down after misses); an adaptive k would take most of the code gain without
the prose loss, exact or with mb.

## Limits

- **Lossy.** KL is measured per position (above); no task-quality benchmark was run. Sampled outputs from both arms of
  mb2 read as coherent text (one prose sample per arm checked by eye).
- Only k=2-4, tp1, batch 1, temperature 1.0, 512-token outputs at short context. Not run: tp2, other temperatures,
  long context, CUDA, Metal.
- HIP sampled speculation itself is off by default (`SampledSpec::default_for`); both arms set it explicitly. Its 56%
  acceptance on chat is the first served HIP run of it at temperature > 0.

Gates (head 30225e1a6, base main 406ac001a): Metal no-op on endor (fleetq #8887: plan show byte-identical, 256 greedy ids
identical short and 4k on 8B and 27B, kernels test 51 / 1136 cases 0 FAIL, goldens PASS, cargo test --workspace exit 0) and
CUDA no-op on spark1 (fleetq #8889: plan show json identical on 35B and 8B, kernels test --quick 106 / 954 cases 0 FAIL).
