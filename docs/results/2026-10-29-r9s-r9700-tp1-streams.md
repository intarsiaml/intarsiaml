# R9S: R9700 TP1, Qwen3.6-35B-A3B NVFP4, multi-stream aggregate decode refresh (1/4/8/16 streams)

2026-10-29. Branch `lane-r9s/tp1-streams`, measured on origin/main `a053f986c` (merge of #261). One AMD R9700 (card 0 of tatooine), HIP backend, tp=1.
The scoreboard's R9700 TP1 multi-stream row (4: 214.9, 16: 259.7) is from 2026-10-25, gen 128, with no 8-stream point; this run re-measures it on
current main with the gen-512 setting the other charted lines use, and adds 8 streams.

## Setup

- Binary: `intarsia 0.0.1` built from `a053f98` in the HIP dev image (`intarsia-hip-dev:rocm7.2.4-rust1.90.0`), build stamp
  `head=a053f98 code-tree=6bd88aa600d4 dirty=no`, tree `~/intarsiaml-tp2-r9s` on tatooine (`scripts/r9s/build.sh`, fleetq #7262, `--load cpu`; `raw/build.log`).
  Pre-flight of `--version` and `serve --help` was fleetq #7263 (`raw/preflight.out`).
- Server (fresh docker container for every round, card 0 only, `HIP_VISIBLE_DEVICES=0 GPU_MAX_HW_QUEUES=1`):
  `serve --backend hip --model Qwen3.6-35B-A3B-NVFP4 --max-batch 16 --spec off --profile-every 0 --mem-budget 29 --max-seq 18432 --no-supervisor`.
  HIP defaults otherwise (graphs, no MTP / no speculation; `--spec` defaults to off and is passed explicitly). The serve log shows "continuous batching: up to
  16 sequences (--max-batch), busy prefill chunk 4096" and a context of 15,410 tokens (`raw/window-2339/serve-*.log`). This is the recipe of the 2026-10-26 tp=1 `b16` rows
  of `2026-10-25-tp2-hip.md` section 10.1, minus the explicit `--spec off`.
- Harness: `localeval speed` (`/opt/code/deepeval`), `--sizes 1024 --reps 1 --concurrency <N,..> --thinking off`, fresh nonce per prompt (no prefix hits), forced output length.
  `scripts/r9s/window.sh` is `scripts/tp2-hip/speed-window.sh` cut to the tp1 arm. Every row has 512 (g512) or 128 (g128) completion tokens in the single-stream row, 1k prompts
  (990 to 993 tokens) and nothing was skipped. The "1 stream" figure is the sweep's single-stream decode row at the same server settings (`--max-batch 16`), not a separate max-batch 1 phase.
- Window: one fleetq job, #7264, `--host tatooine-r9700,tatooine-r9700-2 --takes-down radiance --quiet gpu,cpu --expect 40 --mem 30`.
  Phases: `g512` = gen 512, 4/8/16 streams, 3 rounds; `g128` = gen 128, 4/16 streams, 1 round.

The gen-128 round is a single measurement, so it has no spread; the 10-25 figures are the median of 4 rounds. The 10-25 server ran `--max-seq 8192`, this one 18432, and a different tree (10-25 origin/main against `a053f98`),
so the 10 to 12 % difference is not attributed to a cause here. The same-week gen-512 tp=1 run of 10-26 (above) already sits at the present level, which puts any change between 10-25 and 10-26 rather than in the
last three days.

The gap between gen 128 and gen 512 at the same code (238.2 / 289.7 against 294.8 / 371.2) is a harness effect, not a different engine speed: the streams' prefill (TTFT 0.36 s at 4 streams,
1.2 s at 16) is a larger part of a 128-token round than of a 512-token one. The aggregate figure's exact accounting was not checked here, so the share is not quantified. Numbers at different gen
lengths must not be put on one chart; the scoreboard row should be replaced by the gen-512 line.

## Limits

- One window, one machine state; the three rounds are three fresh servers back to back (about 1 min each), not spread over time.
- The gen-128 figures are a single round.
- 8 streams was not measured before, so it has no prior to compare against.
- Single-stream decode here is with `--max-batch 16` (the batched engine), not the max-batch 1 engine of the 10-26 `b1` phase (164.4 there against 164.2 at `--max-batch 16` in the 10-26 `b16` phase, so no visible cost).
