## Brief + progress (kept current; survives context compaction)

**Brief.** `--mtp-draft-vocab N` keeps the first N lm_head rows, and the Qwen3.5/3.6/3.8 tokenizer puts ASCII / Latin below 95726,
Chinese at 95726..~147k and Cyrillic / Arabic / Hangul / kana above ~147k, so a prefix head can never draft those scripts
(`docs/results/2026-11-14-dvocab.md`: Chinese thinking-off 0.76x at N = 65536; 131072 fixes Chinese only and costs 2-3 points on
English / code at 2 streams). Goal: an **opt-in** draft head over a **chosen subset** of rows (~65k) that keeps the 65536 prefix's
English / code speed and drafts every script about as well as 131072.
- Design to verify: gather the chosen rows into one contiguous sub-head at load, existing GEMV / argmax on it, map back through a
  u32 id table; backend code only the gather / copy, no new kernels if avoidable; TP = 2 out of scope but not broken.
- Subset from the 35B's own generated tokens on a mixed prompt set (English, code, Chinese, Cyrillic, Arabic, Hangul / kana, tool
  JSON, thinking on / off), count frequencies, fill the rest by prefix / smoothed frequency; always the special / tool / think tokens.
  File keyed to the tokenizer fingerprint + a `scripts/` builder; checked in; knob `--mtp-draft-subset <file>` /
  `INTARSIA_MTP_DRAFT_SUBSET`, documented in `docs/tuning.md`. CUDA + CPU reference; other backends refuse clearly.

## Design (as built)

- **Knob.** `--mtp-draft-subset FILE` (any command that loads a model; env `INTARSIA_MTP_DRAFT_SUBSET` when the flag is absent).
  Needs `--spec mtp` or a recipe MTP default (the 35B on CUDA drafts by default); an error with another `--spec` and with an
  explicit `--mtp-draft-vocab N`. It wins over the recipe's `draft_vocab` (the 27B recipe's 65536). Unset: no code path changes
  (`LoadOptions::mtp_draft_subset = None`, `Model::draft_map = None`, the prefix / full head exactly as before).
- **File** (`crates/intarsia-core/src/draft_subset.rs`): text, `# intarsia mtp draft subset v1`, `# tokenizer <fp>`, `# rows N`,
  then ascending ids / inclusive ranges. N a positive multiple of 8. `<fp>` = FNV-1a 64 of the **BPE vocabulary** (`model.vocab`
  of tokenizer.json in id order); the CLI refuses a file whose fingerprint differs from the model's tokenizer.json. Added tokens are
  not in the fingerprint, so Qwen3.6-35B-A3B and Qwen3.8-27B (same 248044-token vocabulary, the 27B adds 7 audio tokens) share
  it (`d312a63678904587`). Checked in: `recipes/data/mtp-draft-subset/qwen3_6-35b-a3b-{32768,65536}.txt` (~140 KB each).
- **Load** (`Model::load`, rank 0 only): the chosen rows of the whole lm_head are gathered into one contiguous `QTensor`
  (`QTensor::gather_rows`: the row-indexed parts, weights and per-row scales, are read back row-major, gathered, uploaded; the
  global scale is shared; EXL3 refuses). A vocab-parallel rank 0 loads the whole head for it, as it already does for a prefix
  past its shard (TP = 2 not measured). The ids go to the device as an i32 table. CUDA and cpu only; HIP / Metal refuse with
  "the <backend> backend has no draft subset head". Memory: the gathered head is a new allocation (the prefix head was a view).
- **Draft** (`Model::draft_head_to_device_into`): the existing projection (same GEMV as a prefix head of the same N) and
  `Op::Argmax` into a one-i32 scratch, then **`Op::Embedding` of that index over the id table** writes the token id into the
  slot the next chained pass and the verify ids read. No new kernel: on CUDA the embedding kernel takes bf16 rows, so the i32
  table is viewed as `[N, 2]` bf16 (the non-vectorised kernel copies 16-bit values bit for bit), on cpu as `[N, 1]` i32.
  Eager, captured (CUDA graph), pipelined and batched drafting all go through this one function. The sampled drafter's widened
  logits row puts each subset row at its token id (`draft_logits_row`, -inf elsewhere). `mtp-dump` refuses the knob (its
  `draft_vocab` metadata describes a prefix).
- **Subset choice** (`scripts/dsubset/build_subset.py`): (1) all added / special tokens below the head's rows (26: chat markup,
  `<think>`, `<tool_call>`, ...); (2) every token the 35B generated in the collection corpus (262 replies, 222k tokens, 26.5k
  distinct ids; `prompts.py` COLLECT: English, code, Chinese, Russian, Arabic, Korean, Japanese, European languages, tool calls
  with a `tools` array; thinking on and off; T = 0.6 seeded); (3) the rest split over scripts in proportion to their share of the
  corpus tokens (latin+code 69 %, han 10 %, arabic 8 %, cyrillic 6 %, hangul 5 %, kana 2 %; floor 1 %), inside a script in id
  order (BPE merge order, roughly frequency). The 65536 file holds 37.7k of ids 0..65535, 10.0k of 65536..131071 and 17.9k
  above 131072 (Cyrillic 5.6k, Arabic 5.9k, Hangul 4.0k, kana 1.8k ids in all).

## Recommendation

**Keep it opt-in; do not replace the prefix head yet.** The subset head does what it was built for: it drafts every script (Russian,
Arabic, Korean / Japanese acceptance +0.14 to +0.34 over either prefix, i.e. +20-46 % tok/s on those languages at one stream, greedy) and wins
the mixed set by 11-14 % against the recommended 131072 prefix, while English and code are flat to +2 % against 131072. But it does
not yet meet the brief's bar on two sets: against P65536 it gives up 2-3 points of acceptance on English (0.664 vs 0.682) and code
(0.814 vs 0.848), and against P131072 it gives up 8 points on Chinese with thinking off (0.532 vs 0.611; -1 to -2 % tok/s). Both come
from coverage (94-96 % reachable on en / code, 82 % on zh), i.e. from a 222k-token corpus, not from the mechanism (Q65536 == P65536
exactly). Next step before any default: rebuild the subset from a bigger corpus (round 2 is being collected) and pick the builder by
cross-validation on the collection corpus, then rerun gates 3 and 4 with that file. For a deployment that serves non-Latin, non-Chinese
traffic the opt-in is already a clear win (`--mtp-draft-subset recipes/data/mtp-draft-subset/qwen3_6-35b-a3b-65536.txt`).
