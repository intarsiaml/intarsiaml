# W4A8 for the Qwen3.8-27B MXFP4 on HIP: fp8 (e4m3) activations (lane W4A8)

User decision 2026-10-26 20:24 EDT: "2 + 1. be cautious of tonights downtime and you can fan out the work before and after the downtime"
(option 2 = this lane: fp8 e4m3 activations for MXFP4 weights, like Radiance, W4A16-level accuracy at W4A4-level speed; option 1 = lane W16,
W4A16 default, merged as #184). Branch `lane-w4a8/fp8-act`. Hardware: tatooine, 2x R9700 (gfx1201), tp2.

Evidence that motivated it (`2026-10-27-act27-27b-w4a16-mmlu.md`, `2026-10-27-mmlu27-27b-quality.md`, full MMLU n=1425): W4A4 0.802,

shows `quant=fp8_e4m3` and the ops `ar_rmsnorm_quant_fp8`, `gate_quant_fp8`.

## 0. Design (written before the first GPU window)

**Mode.** `Mxfp4Act::Fp8` (`--mxfp4-act fp8`, alias `w4a8`; recipe key `[defaults] mxfp4_act = "fp8"`), the third value of the op's `act [1] f32`
input (0 = 16-bit, 1 = dynamic MXFP4 QDQ, 2 = fp8). Opt-in; the 27B default stays W4A16 (lane W16) until the gates below decide.

**Numerics (the CPU reference defines them; every kernel is graded against it).**

```
weights   W[n,k] = e2m1(code) * 2^(sw[n,k/32] - 127)       exact in e4m3 times a power of two: e2m1 magnitudes {0,.5,1,1.5,2,3,4,6}
per token xs[m] = max(amax_k |x[m,k]| / 448, 1/(448*512))   f32; Radiance's dynamic_per_token_scaled_fp8_quant (radiance_mxfp4.py:154-166)
          xq[m,k] = e4m3fn(clamp(x[m,k] / xs[m], -448, 448))   f32 division, round-to-nearest-even, saturating
output    y[m,n] = xs[m] * sum_g 2^(sw[n,g]-127) * ( sum_{e<32} e2m1(w[n,32g+e]) * xq[m,32g+e] )     fp32 accumulation on the device
```

The weight reaches the matrix core / dot unit unrounded: the e8m0 group scale is applied after the 32-element dot (or folded exactly into
e4m3 when a row's scale span allows it, below). Quantising to fp8 (a float format) keeps 3 mantissa bits for every element inside the scale's
range; the per-token scale only has to bring the row into e4m3's 2^-9..448 span, so per-token is nearly as accurate as per-32 groups and is
what Radiance runs. Cost of per-token: for row-parallel layers (o_proj, down_proj) each tp rank scales over its own K slice, so tp2 is not
bitwise tp1 for W4A8 (W4A4's per-32 groups are). The same quality evidence is on tp2.

**Plumbing.** `QTensor::act_fp8` (with `act_quant` true), `OpAttrs::mxfp4_a8` -> `ShapeInfo::mxfp4_a8`. Every existing MXFP4 kernel on HIP, CUDA
and Metal declines `mxfp4_a8` calls (they read any nonzero `act` as W4A4); the CPU reference branches on exactly 0, 1, 2 and refuses other values.
`--mxfp4-act fp8` on CUDA/Metal therefore finds no kernel (clear failure, no silent W4A4).

**HIP kernels** (new files, the existing kernels are untouched):

| kernel | rows | what |
|---|---|---|
| `matmul_mxfp4_a8_gemv`, `matmul_mxfp4_pair_a8_gemv` | M 1..8 | solo decode (priority 10) |
| `matmul_mxfp4_a8_gemv_rows`, `matmul_mxfp4_pair_a8_gemv_rows` | M 1..16, `rows_exact` | batched / speculative rows; the same kernel family as above, so a row is bitwise the M=1 call by construction |
| `matmul_mxfp4_a8_mma` | any M | prefill GEMM on the fp8 x fp8 WMMA |

* `kernels/hip/ik_mx_a8.h`: the per-token quant pre-pass (`mx_a8_quant_kernel`, one block per row: amax, `xs`, e4m3 bytes via `__fdiv_rn`,
  clamp, `v_cvt_pk_fp8_f32`, the sequence of `f8r_quant8`), scratch layout (`xq` at 0, `xs` at `(M*K+15)&~15`), and the e2m1 -> e4m3 byte decode.
* `kernels/hip/mxfp4_a8.hip`: decode. `mxfp4_a8_rows_kernel<M>`, 2 weight rows per warp, 8 warps, the lane-to-group map and xor-butterfly
  of the W4A4 rows kernel; per 32-group `t = v_dot4_f32_fp8_fp8` chain (8 instructions) over weights decoded to e4m3 with `v_perm`, then
  `acc = fma(t, 2^(sw-127), acc)`, `y = warp_sum(acc) * xs[m]`. Falls back to `v_cvt_pk_f32_fp8` + fp32 fma when the builtin is absent.
* `kernels/hip/mxfp4_a8_gemm.hip`: prefill. The tile structure of the W4A4 fold GEMM (`matmul_mxfp4_mma_fold`): A = weights decoded to
  e4m3 in registers, B = the quantised activations, fp8 WMMA, double-buffered 64-k stages. Fold path: when every row's scales span <= 14
  octaves the weight is folded exactly to `e4m3(mag * 2^(s - rowmax + 6))` and one GEMM runs over all of K, `y = ldexp(acc * xs, rowmax - 133)`;
  per-group path otherwise (or `INTARSIA_HIP_MXFP4_A8_PERGROUP=1`): two WMMAs per 32-group into a zeroed tile, then `acc += tile * 2^(sw-127)`.

Not done on purpose (first version): fusing the activation quant into the rmsnorm / all-reduce (Radiance fuses it); the separate pre-pass
costs one small launch per projection. Done later only if the timings say the pre-pass matters.

## 1. Gates (decided from measurements only)

1. MMLU n=1425 (the act27 localeval command) >= 0.820.
2. KL vs the W4A16 golden (`qwen3.8-27b-mxfp4-hfquark-w4a16-top20`, `--golden`) no worse than W4A16's own by more than the noise floor.
3. Speed at tp2 with MTP default: prefill (4k) and decode (1024/4096 prompts, 7 localeval categories x3 interleaved) faster than W4A16, target >= W4A4.
4. MTP ids: 18/18 spec-on == spec-off under W4A8; batched rows == solo.
5. Kernel admission + >= 3 planted mutants caught; G0 for the other models unchanged (`plan show` + ids for the 35B and 8B on HIP).

If gates 1 and 3 cannot both pass, `--mxfp4-act fp8` ships opt-in with the numbers.
