# TP=2 self-golden budget: measured noise, derived budget, and why it is not shipped

Date 2026-10-13/14. `tatooine` (2x R9700 gfx1201, ROCm 7.2.4, `intarsia-hip-dev:rocm7.2.4-rust1.90.0`, `GPU_MAX_HW_QUEUES=1`),
Qwen3-8B BF16 (`/models/Qwen3-8B`), goldens `/models/golden/qwen3-8b-long-fp32.safetensors` (self-golden prompts, 10 prompts,
1434 prefill / 160 decode positions) and `qwen3-8b-fp32.safetensors` (434 / 128). Build `head=192f652 code-tree=0da171c71cb8
dirty=no` (`scripts/tree-stamp.sh`, `INTARSIA_BUILD_STAMP`; the `hip`-feature binary, checked for the stamp and for the absence of
the "built without the hip feature" string before the first burst). Branch `acc/tp2-budget` on `arch/plan` (6418ef1); the binary measured is 192f652, and the final commit only adds tests, scripts and docs
(`model.rs` and `provenance.rs` are the same as in 192f652).
Method and conclusion: [accuracy.md, "TP self-golden budget"](../accuracy.md). Context: [ADR-0006](../decisions/0006-tensor-parallelism.md),
[phase 2b results](2026-10-13-phase2b-tp.md). Raw logs: `2026-10-14-tp2-budget-logs/`; table generator
`scripts/tp2-budget-summarize.py <logs dir>`; bursts `scripts/tp2-budget-burst.sh` + `scripts/tp2-budget-remote.sh` (stages `m1`..`m4`).

## Verdict

**Literal result of the requested test**: `INTARSIA_TP_TEST_BUG=scale:1.01` (rank 1's partial times 1.01 before every
all-reduce) **FAILS** the derived budget, on one check only: the prefill largest-position KL (2.2e-1 against 9.8e-2). That
statistic also trips on a 0.1% bug (1.1e-1) and reads 1.6e-1 for a clean tp=2 variant against a tp=2 dump, so it is reading
position-level noise, not the bug. The other realisations pass every check: 1.01 on rank 0, and 1.01 on the short golden's
prompts. The mean KL, flip and worst-prompt checks separate a bug from clean only from 2% (long golden) or 3% (short).

**The budget is derivable but is not shipped.** Measured noise gives a TP budget (k = 2, the envelope's), tp=2 passes it with
margin, and tp=2's distance to the fp32 golden is inside the spread of tp=1's equivalent variants (long golden). But the
derived budget does not reliably catch a 1% partial-scale bug, so by the rule set for this work it does not ship. The
fp32-golden floor does not catch 1% either (it catches 2%). The guard that catches 1% is the Mac f32 tp=2-vs-tp=1 test
(23000x separation; backend-neutral sharding and reduction logic with the host communicator only; a HIP-specific model-level
bug would not reach it, `comm.rs` covers the collective kernel exactly). Default self-golden budgets and the gate code are
unchanged.

budget = max over the tp=1 variants x k, k = 2 (`envelope::DEFAULT_K`, unchanged). The `max` rows are the bold figures above.

| check | max over tp=1 variants | derived | tp=2 observed |
|---|---|---|---|
| mean 21-way KL | 6.07e-4 | 1.2e-3 | 5.9e-4 / 5.1e-4 |
| largest position KL | 4.9e-2 | 9.8e-2 | 5.0e-2 / 1.5e-2 |
| top-1 flips (prefill) | 6 | 12 of 1434 = 0.84% | 5 |
| mean \|tail diff\| | 2.1e-4 | 4.2e-4 | 1.5e-4 / 2.1e-4 |

Clean tp=2 passes all five (also on the short golden's prompts), the P2P and host communicators identically.

## 4. Bug injection

`INTARSIA_TP_TEST_BUG=scale:F[@RANK]` (test-only; `Model::all_reduce`, host round trip; listed under `fault` in the exec diff):
rank `RANK` (default 1) multiplies its partial by `F` before every all-reduce (72 per decode step). Self-golden columns are the
bug against `S0`; "derived budget" is the table of section 3 applied to them; floor is the bf16-class gate against the fp32
golden (long golden unless noted).

| bug | prefill mean KL / max pos / flips | decode mean KL / max pos | derived budget | fp32 floor |
|---|---|---|---|---|
| 1.001 rank 1 | 6.02e-4 / 1.1e-1 / 8 | 4.25e-4 / 6.3e-3 | FAIL (max pos, one position) | pass (3.98e-4) |
| 1.003 rank 1 | 5.40e-4 / 6.4e-2 / 5 | 5.19e-4 / 9.1e-3 | pass | pass (4.31e-4) |
| 1.005 rank 1 | 5.46e-4 / 4.9e-2 / 8 | 5.21e-4 / 1.2e-2 | pass | not run |
| **1.01 rank 1** | 9.34e-4 / 2.2e-1 / 7 | 6.96e-4 / 1.9e-2 | **FAIL (prefill max pos only)** | **pass** (6.73e-4, top-1 99.51%); short pass (4.21e-4) |
| **1.01 rank 0** | 7.43e-4 / 7.2e-2 / 5 | 5.82e-4 / 1.1e-2 | **PASS** | not run |
| **1.01 rank 1, short golden** | 4.34e-4 / 4.5e-2 / 0 of 434 | 5.81e-4 / 1.1e-2 | **PASS** | |

| 1.03 rank 1 | 2.47e-3 / 5.3e-1 / 10 | 2.02e-3 / 5.2e-2 | FAIL | FAIL (2.18e-3) |
| 1.05 rank 1 | 5.40e-3 / 8.8e-1 / 19 | 3.76e-3 / 8.6e-2 | FAIL | FAIL (5.05e-3) |
| 1.1 rank 1 | 1.88e-2 / 2.4 / 38 | 1.39e-2 / 4.0e-1 | FAIL | FAIL (1.85e-2) |

Bug runs were not repeated (clean tp=2 is bit-reproducible: second run and host comm give the same figures). The rank-0 /
rank-1 difference and the short-golden miss are the evidence that the one catch is not a property of a 1% bug. The Mac f32 test (`crates/intarsia-models/tests/tp_test_bug.rs`): tp=2 against the unsharded model,
clean rel_l2 of the logits 2.5e-7 (bound 1e-5), `scale:1.01` 5.7e-3.

**Decision**: 1% is not reliably caught by the derived budget (one of three realisations, by one statistic) nor by the floor
(0 of 3), so the budget is not added to the gate. TP regressions of 2% and more are caught by both; 1% and below only by
the Mac f32 test and the exact collective tests.

## 5. What was shipped

- `crates/intarsia-core/src/model.rs`: `INTARSIA_TP_TEST_BUG=scale:F[@RANK]`, test-only bug hook (a malformed value is an
  error; unset costs one `Option` check per all-reduce).
- `crates/intarsia-cli/src/cmd/accuracy/provenance.rs`: the variable is recorded as a fault in the exec diff, so a dump or run
  made under it is labelled.
- `crates/intarsia-models/tests/tp_test_bug.rs`: Mac tests (hook moves the logits; scale 1.0 is the identity; malformed value
  refused; f32 tp=2-vs-tp=1 separates a 1% bug from summation order by 23000x).
- `scripts/tp2-budget-burst.sh`, `scripts/tp2-budget-remote.sh`, `scripts/tp2-budget-summarize.py`: the bursts and the table.
- `docs/accuracy.md` "TP self-golden budget", this file and its logs.
- **Not** changed: `selfgolden.rs`, the default budgets, any flag. There is no TP budget flag.

Reproduce: `rsync -a --delete --exclude target --exclude .git --exclude golden --exclude tools/.venv --exclude bench-out . tatooine:~/intarsiaml-tp2b/`;
build `fleetq run --host tatooine --mem 0 ... -- ssh tatooine 'cd ~/intarsiaml-tp2b && INTARSIA_REPO=$HOME/intarsiaml-tp2b INTARSIA_TARGET_VOL=intarsia-cargo-target-tp2b deploy/tatooine/dev.sh env INTARSIA_BUILD_STAMP="$(scripts/tree-stamp.sh)" cargo build --release -p intarsia-cli --features hip'`;
bursts `fleetq acquire --host tatooine --takes-down radiance --mem 30 ... --wait`, then
`FLEETQ_JOB=<id> ssh tatooine 'FLEETQ_JOB=<id> TAG=measure bash ~/intarsiaml-tp2b/scripts/tp2-budget-burst.sh m1'` (then `m2`, `m3`, `m4`
on the same build), `fleetq release <id>`. (`--mem 60` per the brief was refused by fleetq as never fitting; `--mem 30` on both
cards, as in phase 2b.)
