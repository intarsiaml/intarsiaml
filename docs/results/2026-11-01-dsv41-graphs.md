# DeepSeek V4.1 Flash: CUDA graphs for the decode and verify passes (lane dsv41/graphs)

Lane `dsv41/graphs`, 2026-11-01, on `dsv41/plan`. Mia EXL3 2.9 bpw checkpoint, TP=2 over spark1 + spark2 (GB10, sm_121).
Base numbers and the blockers this lane removes: docs/results/2026-11-01-dsv41-tp2.md, "Step 3: CUDA graphs for DSv4.1
decode" and the speculation section.

## Step 1: device-position kernels

Every positioned op (`RopeTail`, `WindowKv`, `AttnSparse`, `CompressPool`, `IndexerBlocks`, `IndexerTopk`, and now
`ActQdq` for the shared-slot writes) takes the pass's first position from `OpCall::pos` (`i32 [1]`) and runs on
capacity-sized views. The rules (docs/design/dsv41-ops.md "Device position (CUDA graphs)"):

- the shared compressed-KV / index-key views span the slot (`Ncap = cap / r` rows); the kernels read `N = (P + T) / r`
  from the device and bound their work by it (score blocks past `N` exit before loading q, the selects run over `N`
  entries);
- top-k width fixed at `Kw = min(index_topk, Ncap)`, `-1` past `min(top_k, N)`; the candidate mask past `ceil(N / B)` is 0;
- the compressor branch is always emitted for `ceil(t / r)` groups; `CompressPool` writes only the completed groups,
  `ActQdq` writes rows `P / r ..` of the whole slot (a pending group's row is rewritten when the group completes, and no
  reader sees it before);
- `AttnSparse` computes its split count and tile partition on the device from `Kc = min(Kw, N)` exactly as the host does
  from its idx width, so the result is bitwise the host call's (grid sized from `Kw`, extra splits exit).

Without `OpCall::pos` every op is unchanged. FFI: `ik_act_qdq`, `ik_rope_tail`, `ik_attn_sparse` gained `ratio`;
`ik_act_qdq`, `ik_compress_pool`, `ik_indexer_blocks`, `ik_indexer_topk` gained `pos` (`kernels/cuda/ik_cuda_abi_dsv41.h`).

**Bitwise device vs host on GB10** (`crates/intarsia-backend-cuda/tests/dsv41_dpos.rs`, 5/5): every op's device call
against the host call on the same buffers over many P, both attention kernels (SIMT, MMA), both indexer score kernels,
bf16 and f32, Ncap = 20000 for the indexer (the select switches between the multi-block and one-block forms at
N = 16384). A captured graph of all seven device calls replays at 11 positions (also backwards) with the eager bits.

capacity is >= 16384 at both ratios): with 8 indexer layers about 30-50 us per pass.

**The device-position graph** (`PassKind::dpos`, `crates/intarsia-core/src/dsv41/graph.rs`): the graph of a pass of up to
16 rows with the rules above; `Step::pos` marks the steps that read the device position; it does not depend on the host
position (built once at position 0, it serves every position). `INTARSIA_DSV41_DPOS=1` runs it eagerly for every pass of
up to 16 rows (prefill chunks keep the host graph).

- cpu f32, 3-layer cache (layers 0-2: ratios 0, 0, 2), `device_position_passes_equal_host_passes`: 110-token prompt,
  then 30 short passes (1 row, 2-4 row chunks across group boundaries): every pass's logits bitwise equal to the host graph's.
- CUDA bf16, GB10, the same test on the 3-layer cache with its DSpark part (fleetq #7724, binary `fb8b0dd26`):

| run | passes | result |
|---|---|---|
| device-position eager vs host, 1100-token prompt (ratio-2 keys past `index_topk`), cap 2048, verify passes mixed in | 39 | bitwise equal |
| CUDA graph replay vs host, same | 39 (25 replays: 1-row and 4-row verify) | bitwise equal |
| CUDA graph replay vs host, 110-token prompt, no speculation | 30 (20 replays) | bitwise equal |

- Stage-5a few-layer parity against the official layer outputs with `INTARSIA_DSV41_DPOS=1` (the 16-row prefill and both
  decode steps on the device-position graph): passes, L2 rel_rms 2.4e-2 (the host graph's number in the tp2 results).
- `verify_rows_track_decode_through_rollback` with `INTARSIA_DSV41_GRAPHS=1` (CUDA): median rel_rms 7.1e-3, worst 0.184 at
  position 134, argmax flips at 134 / 155 / 167: the host graph's numbers exactly.
- `speculative_greedy_equals_plain_greedy` on CUDA bf16 gives leading 4/48 equal tokens with graphs off, device positions
  on, or graphs on, token for token the same as the binary from before this lane (`8589037c5`): the 3-layer model's
  bf16 near-tie at token 4, not a graph effect (the test's exact form is cpu f32, 48/48).
