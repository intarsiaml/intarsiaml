## Pass rules (fixed before the first window)

**A. NCCL arms, kill test.** `nccl_bench` (the engine's own `Comm`) between the Sparks, payloads 16 KiB .. 128 KiB (stand-ins for the three small decode collectives), 1 MiB, 21176320 B (a 1034-row chunk) and 41943040 B (2048 rows). Arms: `NCCL_PROTO` default / Simple / LL128 x `NCCL_MAX_NCHANNELS` 2 / 4 / 8 x `NCCL_BUFFSIZE` 1 / 4 / 8 MiB (27 arms; the baseline is the shipped env: default, 2, 1 MiB). `NCCL_DEBUG=INFO` runs (subsystems INIT, TUNING, COLL) at 42 MB for the arms whose buffer is 1 or 8 MiB record the algorithm, protocol and channel count NCCL chose. An arm is a candidate only if its ar_inplace `sync` time at every payload from 16 KiB to 128 KiB is at most the baseline's + 30 us. **Kill A if the best candidate's 42 MB bandwidth is under 1.3 x the baseline arm's** (measured in the same run; the baseline must also land within about 25 % of the trace's 14.6 GB/s, else the bench does not represent the engine and that is reported). If A passes: sessions X (current env) and Y (best arm), ABAB.

**B. Cold first all-reduce.** `nccl_bench NB_COLD`: 10 rounds of a 3 s idle then (a) one 42 MB all-reduce, (c) the same again at once, and, after another 3 s, (b) a lead all-reduce (16 KiB, and in a second run 4 MiB) followed 7 ms later by the 42 MB one. **Reproduced** if after-idle >= warm + 2000 us. **Hidden by a lead** if (b) is within half of the excess of the warm figure. Only then is the opt-in warm-up (`INTARSIA_DSV41_COMM_WARM=<KiB>`, the smallest lead payload that hides it) run as session W, and as nsys sessions Xn / Wn (the 4K prompt three times, rank 0 and rank 1) to read the first all-reduce of each request; it is kept only if the first all-reduce falls to within 1 ms of the median and no prefill figure gets worse by more than the run-to-run spread. It stays opt-in (default off) in any case: it adds a collective, and a value that differs between the ranks hangs the group.

**C. Engram hot tier.** Z (`INTARSIA_DSV41_ENGRAM_HOT_MB=0`) against X (1024, what `run-full.sh` and every measurement used). Same sessions, same order inside a session (golden ids first, then the localeval prefill speed, then the category decode), so the tier fills the same way in each. **Make 1024 the code default if** decode by kind is faster for X than Z in both rounds by more than 2 % on at least one kind and not slower on any by more than 2 %, or prefill is faster at 1K or 4K by more than 2 % in both rounds; if Z is equal within those margins the default stays 0 and the tuning row is only corrected to say it was measured. The size is not swept (1024 MiB is what was measured; MemAvailable stays above the 5 GiB line in every run with it).

**Bit identity.** Round 1 of each session runs the golden prompt set (`tools/dsv41/golden_tf.py tokens`, 10 prompts x 64 greedy ids = 640 ids). Every arm (Y, W, Z) must give the same 640/640 ids as X in the same window (`replay-test-lib.py tokcmp --require-identical`). X is the current binary at the shipped env, i.e. main's behaviour; the only code in the binary beyond main is the opt-in warm-up (off in X, Y and Z).

**Speed.** `localeval speed --sizes 1024,4096,16384 --gen 8 --reps 3` (the prefill3 shape) and decode by kind with `catspeed.py` over `categories-rcp` + `chat-rcp` (32 requests, 256 tokens), chunk 2048 (the engine default), CAP 66000, session order X Y W Z X Y W Z. Memory: `mem.log` and `memfine` minima per session against the 5 GiB kill line, compared between sessions.
