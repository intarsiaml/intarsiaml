2026-10-29. Branch `lane-r9t/tp2-streams`, measured on the binary of origin/main `a053f986c` (main is `971a67d2b`; the two differ by docs and script commits only, `git diff --stat a053f98 971a67d2b -- crates/` is empty).
Both AMD R9700s of tatooine, HIP backend, `--tp 2 --devices 0,1`. The scoreboard's R9700 TP2 multi-stream row (4: 358.5, 16: 530.0, gen 512) is from 2026-10-26 (`2026-10-25-tp2-hip.md` section 10.1) and has no 8-stream point; this run

Reading the table:

- TP2 is level with the scoreboard everywhere (decode within 0.7 %); prefill is 1.4 to 5.1 % higher.
- TP1 decode is +0.7 to +0.8 %, and prefill at 4k and 16k is level (+0.5 %, -0.1 %). The 1k prefill is the odd one: w1 gave 5037 / 4913 / 7248 (TTFT 0.20, 0.20, 0.14 s), w2 gave 7533 / 6260 / 6723 (TTFT 0.13, 0.16, 0.15 s),
  the six-round median is 6492 against the scoreboard's 7214 (-10.0 %), and the 10-26 `b1` TP1 row was 7199 (7175-7242) with a tight range. The two w1 rounds near 5000 and the low 4k of w1 round 1 (8795, TTFT 0.47 s)
  did not recur in w2, whose 4k and 16k rounds are tight (4k 10408-10419, 16k 9435-9525). The 1k prompt is under 1024 uncached tokens, so its TTFT is partly per-request overhead, and 1k prefill on TP1 is visibly
  noisier here than it was on 10-26 (w2 alone spans 6260-7533). The cause was not found (not examined: clocks / power state of a card that was idle before w1's first rounds, a first-request effect at max-batch 1, anything else);
  so the -10 % at 1k is a measured median, not an established regression, and needs a quieter repeat if it matters. The scoreboard cell carries the six-round medians and the 1k range.
- The TP1 scoreboard row is the H3 run with macro prefill 8192; this run uses the binary's defaults at max-batch 1. The 4k and 16k prefill figures agree with H3 to 0.5 %, so the same path appears to be in use; that was not checked in the server log.
