### Lane 1: row-invariant small-row GEMV family (fp8 dense, NVFP4, bf16 router/gate; MXFP4 for the 27B), 1 to 16 (to 64) rows
| | |
|---|---|
| Why | B=16 profile (`hr3` s4, 54.95 ms synchronised step): `matmul_fp8` 14.17 ms (25.8%, 130 calls, 109 us each), `matmul_nvfp4` 7.61 (13.9%), bf16 `matmul` 6.03 (11.0%), together 27.8 ms = 51%. Byte floors at 640 GB/s: fp8 about 2 ms (about 1.28 GB of dense weights), nvfp4 about 0.6 ms, bf16 router/gate about 0.1 ms. The fp8 GEMV time grows 2.5x from B=4 to B=16 because the `_rows` kernels are ALU/LDS-bound past 4 rows (hb s1 micro-timings: fp8 2048x4096 18.9 / 22.5 / 44.8 / 90.5 us at M=1/4/8/16; nvfp4 head 410 / 769 / 3272 us at M=1/4/8). 16 rows is exactly one WMMA tile, so weights can be read once. |
| What to port | radiance `libr4d/r4d_gemm_mxfp4a8_gemv.hip` (348 lines): `gemv` (M<=8, WMMA from register fragments, `v_dot4` for K%128!=0, lines 52-155), `gemv_wide` (9-64 rows, up to four 16-row tiles per wave so each weight word is loaded and folded once, lines 168-260), launcher `mxg_launch` 263-316; `libr4d/r4d_mxfp4.h` (78 lines, e2m1 to e4m3 `v_perm` fold); `r4d_gemm_mxfp4a8_decode.hip` (681, split-K, 65-128 rows; optional); dispatch table `libr4d/README.md:116-220`, `r4d_rows.cpp`. Structure to copy: weights go from global to registers with non-temporal loads, no LDS staging; 8 waves split K and meet once in LDS; form chosen from K only, so **a row's bits do not depend on M** (verify's first row equals plain decode). Two column tiles only when M>24, N>=4096, K>=3072 (one tile re-read the activation N/16 times). intarsia targets: `kernels/hip/fp8.hip` (`matmul_fp8_gemv_rows`, `fp8_gemv_pair_kernel`), `kernels/hip/ik_f8_gemm.h` (already wraps `v_wmma_f32_16x16x16_fp8_fp8`), `kernels/hip/nvfp4.hip` (`matmul_nvfp4_gemv_rows`), `kernels/hip/matmul.hip` (bf16/logits rows), `kernels/hip/mxfp4.hip` + `ik_dq_gemm.h` (27B), registry `crates/intarsia-backend-hip/src/kernels.rs`, `quantmoe.rs`. |
| NVFP4 caveat | radiance's fold relies on one E8M0 exponent per 32 K plus a per-row reference exponent, so block scales merge into the e4m3 element losslessly. NVFP4 has an e4m3 block scale per 16 K that cannot merge into an e4m3 element. For NVFP4 apply the scale per WMMA k16 as 8 FMAs on the partial sum; hp priced this at 360.7 TFLOP/s in a register-only microbenchmark (`2026-10-22-hp-hip-prefill-roofline.md` s7), so the scale fold itself is affordable. The fp8 dense weights (per-tensor scale) need no fold. The MXFP4 27B layers can use radiance's fold directly. |
| Design decision for the user | **Option A (bitwise)**: restructure the VALU `_rows` kernels (lower ceiling, keeps G-B against the existing 1-row kernels). **Option B**: one WMMA family for every M including M=1 (radiance's approach). Row bits then do not depend on M, so G-B/G-C, MTP-verify equality and batch invariance hold *inside the new family*, but the **solo decode path changes bits once** vs today's GEMV (hb negative control proves WMMA != GEMV at M=1: 1 of 8192 elements differs). Gate: acc-short golden + KL vs ref-noise, 256-id identity new-vs-new across batch sizes. Options cannot be mixed. Recommend B for dense fp8 and bf16 router (small K), measure first. |
| Expected gain | Ceiling: GEMV classes 27.8 ms profiled to about 8-12 ms, i.e. about 15 ms of a 55 ms synchronised step (about 28%) at B=16, about 8-10% at B=4 (GEMV is about 45% of the 14 ms step there, floor-limited). Discount for launch floor (3.6-4.5 us/launch x 130 fp8 calls = 0.5 ms) and imperfect bandwidth: **plan on +15-25% aggregate at 16 streams, +5-10% at 4, 0 at 1.** Evidence for realism: radiance got 1% / 5% / 14% at c1/c4/c16 replacing already-decent rows (5a9ce49 message) and measured median -10.3% kernel time over 192 shape cells (`libr4d/README.md:194`). |
| Numerics | A bitwise; B numerics-changing once (then self-consistent) |
| Effort | 30-45 h (fp8+bf16 first 15-20 h; NVFP4 scale fold next 10 h; MXFP4 27B port 8 h; tests, G-B extension, mutants) |
| tatooine GPU | about 3 h over 6-8 windows, one card (microbench, G-B/G-C 35B ran in 205 s, goldens, speed A/B). Speed A/B needs a quiet window. Takes radiance down each window. |
| Gate | `rows_exact.rs` G-B (every M=1..16, new kernel row r == new kernel M=1), G-C 35B bitwise batch identity (17,550 pairs), acc-short + golden KL (option B), `INTARSIA_HIP_GB_CONTROL` negative controls, no-op `plan show`/256 ids vs main for A |

| | |
|---|---|
