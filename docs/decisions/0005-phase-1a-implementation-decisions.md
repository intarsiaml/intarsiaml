# ADR-0005: Phase 1a implementation decisions

_Drafted by fleet model `guidance` from the raw note; checked against the note by Claude 2026-10-13_

Status: Accepted
Context: Phase 1a agents (workflow wf_876ddc13-5f8, 2026-10-13) made implementation decisions. Accepted by Claude as the Phase 1a baseline (commit 4963b43). Results: docs/results/2026-10-12-phase1a.md.
Decision:
- Queue bound and cancel live in the server layer, with a core hook: The queue bound is an atomic in-flight counter in the server (max_queue + 1 slots) released by the bridge thread, so it is race-free without touching the engine. Cancellation needed core support: GenRequest.cancel (Option<Arc<AtomicBool>>), set by a drop guard on the HTTP receiver, because the old mechanism only noticed a gone client when the next token was sent, never during prefill.
- Stop sequence carried on GenEvent::Done, not FinishReason: FinishReason is Copy and used by value across crates, so the matched string went into Done.stop_sequence as an additive field. StopMatcher records which string matched.
- Supervisor uses libc signal and std::process, no tokio process feature: Added workspace dep libc = "0.2" (already in Cargo.lock). The supervisor polls try_wait and an atomic signal flag; SIGTERM is forwarded to the child with a 30 s grace, then SIGKILL. The child's watchdog exits with 86/87 and arms an abort after 5 s in case exit hangs on a wedged driver.
- Load errors are fatal for the supervisor (exit 78): A bad model path or recipe cannot be fixed by a restart, so the child exits 78 on load failure and the supervisor stops. Bind errors and crashes after load restart with backoff.
- Prefill split in generate_one, not inside Model::forward: To check cancel between chunks without changing Model::forward's signature (others edit model.rs), generate_one feeds all but the last chunk via forward(HeadMode::None) using the new Model::prefill_chunk() accessor, then picks the first token from the final chunk. State commits per chunk exactly as before.
- mem_budget is GiB total process budget: --mem-budget GIB caps weights + workspace + KV; the KV budget is min(free * kv_fraction, budget - weights - workspace). Added as MemoryPlan::compute_budgeted so the existing compute signature and tests are unchanged.
- Debug env hooks apply in every build: INTARSIA_DEBUG_STALL_S and INTARSIA_DEBUG_PANIC are read at the start of each job in the worker, documented as debug-only, so the supervisor test can run against a release binary.
- Router generic over state: intarsia_ui::router<S>() returns Router<S> so it merges into the server's Router<AppState> before with_state; server has one additive edit gated by ServerConfig.ui.
- Decode rate estimate while a request runs: Token counters are booked only when a request finishes, so mid-request rates were 0. The Bus uses steps/s as an approximate decode tok/s (shown with a ~ prefix) when running>0 and the counters are flat; documented in observability.md.
- No per-API edge split: Telemetry has no per-API counters, so both API edges light when work is active; tooltip says the split is not exported.
- Assets live in repo-root web/ via include_str! paths: crate is publish=false so ../../../web paths are fine; modules are served with no-cache so a rebuild is enough to see changes.
- Plan is recorded from the real forward path: Model::dry_run runs run_chunk and the heads with a recorder installed in exec, so blocks other agents add (linear attention, MoE) get planned and admitted automatically with no per-block code.
- Admission runs on clamped, exact-K shapes: Rows, N and positions are clamped (rows 32, N 16384, positions 2000) to keep the f32 reference affordable; K, heads, head_dim, dtypes and attributes are exact. Ops or weight types without a case builder (packed or quantised weights) fall back to the kernel's own sweep, once per kernel. The cuda agent will need to extend admission::case_from_call for NVFP4, FP8 and MoE ops.
- Strict top-1, no invented thresholds: fp16 ties count as disagreement (reported separately). fp8 and 4-bit classes gate only KL because ARCHITECTURE section 6 defines no top-1 threshold there; --min-top1 adds one.
- Top-k KL stated as a support-restricted lower bound: Both distributions are renormalised over the reference's top-k ids; top-1 uses our full-vocabulary argmax.
- Stop strings wait for min_tokens: Matches vLLM. This is a small behaviour change beyond what was asked.
- Admission cache keyed by executable size and mtime: Stands in for a kernel-pack hash, so every rebuild re-admits. Cache files older than 14 days are pruned.
- Default gates not loosened: The 8B cuda prefill top-1 of 99.44% against 99.5% is reported as a FAIL.
- Quantised matmuls and MoE are new Ops: matmul_fp8, matmul_nvfp4, moe_topk, moe_experts, moe_combine. Weight tensors are op inputs in checkpoint layout (no repacking), and routed experts are stacked per layer into one buffer per matrix kind with gate rows then up rows. That keeps dequant_ref equal to checkpoint semantics and gives the plan and admission exact shapes.
- FP8 activation mode lives in the op's scales tensor: scales = [weight_scale, input_scale]; input_scale <= 0 means W8A16. Kernels branch on it on the device, so one kernel serves both modes. The per-recipe option is [defaults] fp8_act = static|none, default static (W8A8, the declared scheme, which vLLM also runs). The accuracy comparison against the vLLM reference is deferred until the 35B model loads.
- Prefill path is dequant-to-bf16 tiles plus mma.sync, not cuBLASLt FP8 or fp4 MMA: The task allows this fallback. It is exact (fp8 and e2m1*e4m3 values are exact in bf16) and deterministic, and passes admission. The fp4 tensor-core path and cuBLASLt FP8 are not done.
- MoE experts kernel groups pairs by expert: It runs three launches (gate+up, down, ordered reduce) over only the active experts. Atomics are used only in the counting sort, and each pair's arithmetic is independent of its slot, so results are bit-repeatable.
- Admission handles the new ops by exact-shape case builders: quant::cases provides the sweeps and the plan-time case_from_call/label, hooked into admission.rs as small additive edits. This closes fixcore's open issue that packed or quantised weights and MoE had no case builders.
- No code copied from TensorFold: The kernels are original and written for our C ABI. Only the prmt fp4-to-e4m3 lookup idea comes from TensorFold, credited in ik_quant.cuh with its MIT copyright line. LICENSES/TensorFold-MIT.txt is added.
- Recurrent state layout and snapshots: One Recurrent slot per GDN layer: f32 conv state [C,K-1], then S [Hv,dv,dk] (dk contiguous) at a 256-byte aligned offset. Prefix reuse for hybrid models goes through snapshots (max 4 per sequence, RECURRENT_SNAPSHOTS), taken after each prefill chunk and one token before the end of the prompt. Reuse is limited to the held sequence, a snapshot, or empty; truncating to 0 always zeroes recurrent state; a failed forward resets the sequence.
- Generic hybrid recipe mechanism: layer.pattern_by_layer (= config layer_types key) plus [layer.by_type] gives the block pattern per layer type, so no Qwen code in the decoder. Unknown layer types, missing types and mismatched keys are load errors. Norm offset is a recipe/model attribute (w_offset op attr, 1.0 for Qwen3.5), not applied to the gated norm inside GDN.
- Op set: Four small ops

- Op set: Four small ops (gate_split, sigmoid_mul, gdn_conv, gdn_delta_rule) with an f64 core::gdn reference shared by ref_* and cpu_f32_*; attrs added to Rope (rotary_dim) and norms (w_offset) so the Qwen3 path is unchanged by default (0 / 0.0).
- Delta-rule kernel design: Sequential over tokens. dk<=128: one thread owns one state row in registers, q/k normalised once per warp and staged in smem, next-token loads overlapped. dk=256: warp-per-row fallback. Conv is tiled over tokens with history from x and a second small kernel to write the new state. Chunked parallel prefill not implemented.
- Tolerance in cuda tiny-model test: A bf16 copy of a random tiny model drifts ~9e-2 rel L2 from fp32 HF just from weight rounding, so the cuda test compares against the cpu bf16 run (1.3e-2) and bounds HF error by 2x the cpu-bf16 error.
- Split-KV serves all q heads of a kv head per block: Each block takes one kv head, one split and one query row, covers all G=N/Nkv heads (G<=8, so the hybrid target's G=8 works) and reads K/V once per group. The same launcher is registered for AttnDecode and for AttnPrefill with m<=16 (verify). Head_dim 32/64/128/256 only; other shapes fall back to the old SIMT kernels, kept at priority 0.
- Split count depends only on kv_len: nsplit = clamp(min(ceil(kv/64), ceil(256/(nkv*rows))), 1, 64), so results are run-to-run identical (Exactness::Deterministic). The Rust copy is used for scratch sizing and must stay an upper bound of the .cu policy.
- Scratch declared as a bound independent of kv_len: Plan probes prefill sizes only at pos0=0, so a size growing with kv_len could be under-reserved for a short chunk at a long position. A unit test covers contexts up to 262144.
- Flash prefill design: FA2-style mma.sync m16n8k16 bf16 with f32 accumulate, 64 rows per block, cp.async K/V double buffering, longest blocks first, P rounded to bf16 before PV (rel_l2 about 2.4e-3, inside the 6e-3 tolerance). Q in registers for D<=128, in shared memory for D=256 (BK=32, 67 KB dynamic smem opted in per device). Registered for m>16.
- CUDA graphs not implemented: The Backend trait has no graph_begin/graph_end/graph_replay, and positions are baked into kernel arguments (rope, kv_append, attention) while split-KV grid dims vary with kv_len. Replay across steps would need position read from device memory and fixed grids in every kernel pack, plus new core trait methods. Not clean, so skipped. The new kernels allocate nothing, never synchronise, and use plan-reserved scratch.
- Debug knob INTARSIA_CUDA_DISABLE: Comma-separated kernel names hidden from the cuda registry, used for the old-vs-new accuracy A/B. It sits in device.rs kernels() so the kernel-table unit tests are unaffected.
- Admission sweep extended: admission.rs belongs to core, but I added long-context cases because split-KV and flash only break with several splits and multiple KV tiles.
- MoE wiring lives in model.rs: Added `Block::Moe`. The recipe's `[layer.moe]` supplies `kind` and `prefix`; the MoE sizes come from the new `ModelDims.moe`, filled when config.json has MoE keys. One `MoeScratch` is shared by all layers and counted in the memory plan. MoE ops go through `Model::exec` via `ExecRunner`, so they get profiling, plan recording and kernel scratch.
- Quantised lm_head: The checkpoint's `lm_head` is NVFP4, so `lm_head` is now a `QTensor` (bf16 stays `Op::Logits`; NVFP4 uses `MatmulNvfp4` with f32 output). The recipe's `tied_to` is only a fallback.
- FP8 activation mode is switchable, default unchanged: Added `LoadOptions.fp8_act` and the `--fp8-act static|none` flag on every model command. The recipe default stays `static` (W8A8), the checkpoint's declared scheme. W8A16 has slightly lower KL on a 10-prompt golden, too small to change the default.
- Gates and 8B failures not loosened: The 8B short-golden decode KL FAIL is reported as a failure with cause undetermined. The 35B 4-bit gate passed on its own terms.
